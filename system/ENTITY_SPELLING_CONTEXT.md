# 已登记名称的场景拼写规范

此功能只帮助按已有资料书写名称，不验证说话者身份或诊断事实。应在已确认转写对象属于提供的名单、项目目录或术语范围时启用。不要把未经确认的公共姓名表直接用于任意私人对话。

每个实体默认不开启。启用后，只有满足全部条件才应用：

- 标准名和源跨度均为3至16个汉字，完整长度和拼音音节一致。拼音比较声母韵母；ASR猜出的字不能证明原音声调。
- 名称在当前领域及通用库中没有另一种同音标准拼写。遇到歧义保留原文。
- 同一分句、名字前后32字内出现配置的独立场景词，累计相关性分数达到设置值。分数不是正确率或模型置信度。
- 姓名首字保持一致；不同姓字、多音误差和近音情况继续保守处理。
- 独立词边界成立，没有切入已有词、跨句标点，且不是账号、路径、书名内部或数字日期表达。
- 实体策略为normalize，模糊模式为auto，并且当前调用允许自动规范。

未配置、preserve策略、关闭或shadow/hint模式继续沿用原行为。成功修改记录为CONTEXT_PINYIN，保留原始ASR文本和修改记录。后续精修失败时保留已经满足条件的名称规范；其它未确认候选仍按原规则回退。

## 医疗术式的完整同音命中

对于 `medical` 领域、`TERM` 类型、`normalize` 策略的 4–16 字中文术式，标准名以“术／手术”结尾时，可仅登记标准名称：在独立术名短句，或“接受／进行／安排／完成／做”等明确术式位置，完整声母韵母相同且标准名唯一的候选可以规范。字形分数偏低不会在验证前将它丢弃。

例如登记“截肢手术”后，选择医疗领域、auto 模式，可以处理“介质手书”或“患者需要接受介质手书”，不需要将错误写法登记为别名。此规则不核验原音声调；同音标准名歧义、已写出的不同身体部位、书信／签名语境、人物姓名位置、标识符及词边界冲突均保留原文。“医生拿到了介质手书”不会被当作接受手术。

其它类型的同音名称仍需语境配置。源文是另一有效诊断或术式时，不能因为它不在本次词表就随意替换。

## 已登记部位名在完整术式中的同音规范

只登记部位名时，如“胰十二指肠”，也可在医疗领域、TERM、normalize、auto 下使用完整拼音证据。源部位名紧接原文已经出现的“切除／修补／置换／移植／切开／造口／消融／成形＋术／手术”，且构成完整的独立术名句，或位于“接受／进行／实施／安排／完成／做”等明确操作位置，才规范已登记的部位名。后面已说出的术式动作保持原样，不生成新的术式词条，也不补缺失词。

“以十二指肠切除术。”及合并窗口中的同一句，可以规范为“胰十二指肠切除术。”。当前部位名限 3–16 字、指定解剖结构词尾。标准名和别称在部位及完整术式两个层面均需无同音目标冲突；源文数字、否定及已经写出的不同部位拒绝改动。

“以十二指肠切除术为例”“以十二指肠为研究对象”“以十二指肠切除术。作为……”继续保留，不能将合法介词“以”推成胰脏的“胰”。书名、作者、手稿、姓名、标识符及询问依据等语境同样拒绝。记录为 `CONTEXT_PINYIN`，理由标记 `medical_procedure_stem_role`，精修失败保留已验证规范。

## 医学正式别称的完整读音

预建库也可以登记有资料支持的等价别称。例如标准名 `ECMO`、别称 `艾克膜`；标准名 `ECMO手术`、别称 `艾克膜手术`。无需登记“埃克莫”等识别错字。

在 `medical/TERM/normalize`、auto 且允许自动规范时，登记的 3–16 字中文别称可提供完整声母韵母证据。要求源跨度长度相同、读音完整一致、当前库内标准名和别称没有另一目标同音，并且紧邻明确设备数量／使用或术式动作位置，如“这台／启动／连接／做／接受”。没有合适位置、多音节近音、医生姓名、作者、书名、标识符及拼写讨论继续保留原文。

较长别称只有在结果等于短别称规范结果加原文未变后缀时才优先。例如“做埃克莫手术”整体规范为“做ECMO手术”，避免前缀竞争挡住完整术名。独立分词边界仍受保护；仅在设备数量位置和明确“不但／不能”等谓词前，允许分词器把末字和“不”误连的特定情况，其它边界冲突不放宽。

修改记录为 `CONTEXT_ALIAS_PINYIN`，精修失败时保留这项已验证规范。此规则不依赖联网推理，也不自动生成实体或别称；资料用于建库审核。`preserve`、关闭实体、非医疗领域和非 auto 模式不启用这一新增分支。

### 显式开启的缩写别称近音

对 `medical/TERM/normalize` 的英文字母缩写（3–12 字母，可附“手术／检查／检测／治疗”），登记的中文正式别称可以复用词条 `allow_near_spelling=true` 权限，默认关闭。这里验证的证据为完整别称读音及明确对象位置；语境关键词权重不代替对象位置。原有中文标准名近音规则仍要求其独立语境评分。

只允许一个音节不同，差异音节只有一个拼音字母编辑，其余音节完整一致。必须在“台／套”等数量位置、紧邻“机器／设备／耗材／机身／管路”，或明确“上／启动／连接／做／接受”等操作位置；允许操作后保留“数十例”等数量。变化音节不能位于已有多字词内部，源文不能是已知完整词，源字符的部位、否定、数量等敏感变化拒绝执行。任何同音或同样近音的其它登记名称／别称都会挡住替换。

例如登记 ECMO 的正式别称“艾克膜”并开启权限，可以规范“第二台埃克姆”“埃克姆机器”“做了数十例艾克姆手术”；“埃克姆医生”“爱科目”“艾克曼”“埃克蒙”仍保留。修改记录为 `CONTEXT_ALIAS_NEAR_PINYIN`，精修失败保留已验证规范。此能力的已有成功仍集中于 ECMO 场景；新一批 31 段录音没有额外收益。

## 医学疾病名称的定义句

在 `medical/TERM/normalize`、auto 且允许自动规范时，预先登记的 4–16 字疾病名称，可在“X是一种／一类（常见、罕见等）疾病／病症／炎症／病变”的明确介绍句中验证完整拼音。只登记标准名即可，不需要维护识别错字别名或额外语境档案。名字末尾限“病／症／炎／癌／疝／障／感染／结石”，当前不覆盖所有疾病名称。

例如登记“腹股沟疝”后，可以把“复古钩扇是一种相当常见的疾病”规范为“腹股沟疝是一种相当常见的疾病”。只有完整长度和声母韵母一致、当前标准名及别称中无另一同音目标、独立边界有效，才允许绕过偏低的字形混合分。ASR 猜出的文字仍不能证明原音声调。

不同读音、源文已写出的不同部位／数字／否定、人物姓名位置、书名、作品、小说和拼写讨论继续保留；不从缺词或部分发音补齐名称，也不判断说话者的诊断是否真实。“布谷钩扇”不符合完整同音；“复骨钩扇”涉及源身体字变化，也不应用这条新规则。成功记录仍为 `CONTEXT_PINYIN`，理由中注明 `medical_disease_definition_role`，精修失败保留该名称规范。

该能力已有一个真人原音片段的有限成功，不代表通用医学实体纠错已经通过验收。

## 可选的单字近音规范

`allow_near_spelling` 默认关闭，可通过 `enable --allow-near-spelling` 或 `spelling_context` JSON 的同名布尔字段对词条单独开启。它仅支持 5–16 字、指定医学术式／症候词尾的 `medical/TERM` 名称：只有一个字不同，其余字和音节均相同，差异音节只有一个拼音字母编辑，且原文未作为另一个实体保护，才继续检查。

不同身体部位、方位、否定、数量和化学元素等变化被拦截；变化处不能切入原文的已知多字词，也不能修改已知完整词、标识符或拼写讨论。候选必须唯一且满足词条语境。新记录为 `CONTEXT_NEAR_PINYIN`，精修失败时保留已验证的实体规范。

比如“二氧化碳储留”在有“呼吸机／潮气量”等独立医疗语境时，可规范为预先登记的“二氧化碳潴留”；不允许把“二氧化氮”换成“二氧化碳”、把“经鼻”改成“经皮”，或将另一药名替换成库内药名。此项不是任意近音纠错。

新配置可把同域词库中其它标准实体作为独立语境词；仍需遵守关键词数量、权重和来源校验。不同词条的内部漏字开关与近音开关彼此独立，导入／导出会保留各自布尔值。读取旧库不启用新选项。

## 可选的长术语内部漏字补全

`allow_internal_omission` 默认关闭，需要对词条单独开启。现有语境配置不会自动获得这个权限。开启后，还必须满足：

- TERM 类型、5至16个汉字；标准名同时存在于独立分词词典中，源写法不是该词典的完整词。
- 源文字只缺一个内部字，其余字完全一致；首字、末两字保留，不补数字、否定、方位等限定字。
- 插入点不能切开原文中已有的词，也不能覆盖其他已保护实体。
- 当前词库只存在一种符合这种漏字形式的标准名称，并满足词条设置的语境分数。
- 标识符、标点边界、拼写讨论等位置不执行补全。

例如已登记“骨质疏松症”、设置“患者／医生”等语境并开启此项时，可以把“患者有骨疏松症”规范为“患者有骨质疏松症”。这不允许替换“骨质增生”等另一病名，也不支持任意近音或英文缩写纠错。成功记录为 `CONTEXT_OMISSION`；精修失败时仍保留已验证的补全。

启用示例（ID 使用实际已登记词条的 ID）：

```bash
PYTHONPATH=. python -m system.entity_context_cli --db /绝对路径/entities.db enable \
  --id 123 --keyword 患者 --keyword 医生 --minimum-score 1 \
  --source '已核实的医疗术语表' --allow-internal-omission
```

JSON 导入在 `spelling_context` 内添加 `"allow_internal_omission": true`。重新执行不含该参数的 `enable` 会恢复仅同音规范；`disable` 会关闭整项语境规范。读取旧库不会迁移或启用这个选项，首次明确启用时才增加所需存储字段。

2026-10-07 的开发回归新增修复一个已见真人录音中的漏字；这是有限收益，不代表广泛近音纠错能力。证据见 `results/entity_rule_optimization_20261007/REPORT.md`。

使用现有页面管理标准名和启停实体。根据本次开发约束，页面和原API没有增加字段；场景配置由实体模块命令管理：

```bash
# 先查看实体ID、来源及现有场景配置。
PYTHONPATH=. python -m system.entity_context_cli --db /绝对路径/entities.db list

# 例：已核实名册中这位记者的标准姓名，配置其使用场景。
PYTHONPATH=. python -m system.entity_context_cli --db /绝对路径/entities.db enable \
  --id 123 --keyword 某报社 --keyword 记者 --minimum-score 2 \
  --source '已核实的本次采访人员名单'

# 仅关闭这个场景规范策略，保留实体和已有明确别名。
PYTHONPATH=. python -m system.entity_context_cli --db /绝对路径/entities.db disable --id 123

PYTHONPATH=. python -m system.entity_context_cli --db /绝对路径/entities.db export --output names.json
PYTHONPATH=. python -m system.entity_context_cli --db /绝对路径/entities.db import --input names.json
```

导入文件为JSON数组。先在临时数据库验证，确认现库没有并发修改后事务合并。未在导入记录中指定的原别名、优先级、策略和启停状态会保留；其他未涉及实体保持。重命名、改类型或改领域会撤销原场景绑定，避免旧资料授权另一个对象。

```json
[
  {
    "canonical_text": "刘艾林",
    "entity_type": "PERSON",
    "domain": "general",
    "normalization_policy": "normalize",
    "source": "已确认使用范围的记者名单",
    "spelling_context": {
      "keywords": {"文本报": 1, "记者": 1},
      "minimum_score": 2,
      "source": "名单已核实；本次稿件的人物标准字"
    }
  }
]
```

独立新闻评测库位于results/entity_context_20261006/context_names.db，包含训练/开发资料提供的标准名与场景。它是评测及演示资料，不自动覆盖当前用户的实体库。当前Web加载每个新会话的实体定义，库数据更新后需开始新会话。

此功能不需要新增模型、联网服务或改变ASR上下文。此次失败的自由纠错及大模型候选方案未接入业务。
