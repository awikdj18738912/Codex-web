## Holdout 021/022 and the removal path

Both synthetic clips reproduce the same local-review failure across current/learned policies and both repetitions. For `linear_holdout_20261012_021`, the completed ASR source contains `随后检查索引，索引交给值班员`; the final text contains only `随后检查索引交给值班员`. For `_022`, source contains `接着核对名单，名单送到调度室`; final contains only `接着核对名单送到调度室`. The source audio/PCM hashes are stable across all four sessions per clip. The trace for `_021` shows the first completed window input `归档结束，归档结束，随后检查索引，` and Refiner output `归档结束，随后检查索引`; the following `索引交给值班员。` is a pending tail and is kept. Once merged, local review sees `索引索引` in `归档结束，随后检查索引索引交给值班员。前面的归档结束说了两遍，需要原样保留。` It returns `REMOVE` with margin 0.5552 and applies the deletion. `_022` has the analogous `名单名单` removal (margin 0.4749). The earlier repetitions named by the instruction are preserved; the later noun repetitions are not. This is a text-trace mechanism, not an acoustic judgment.

The narrowest useful commit point is immediately before applying a local reviewer's `REMOVE` in `system/web_app.py`'s local deletion review path (around the candidate `edited` construction), while the candidate offsets and source-owned refinement spans are still available. Final-only `restore_preserved_repetitions(raw_text, clean_text)` already runs after final entity normalization, local review, and deterministic cleanup, but its source protection only covers patterns recognized by `protected_repetitions`; these comma-separated noun pairs have no cue attached to them. Broadening the general comma-pair rule would also block genuine stutters such as `接着确认，确认货位`, so do not protect every repeated pair separated by a comma.

Any narrowly scoped safeguard should be source-span anchored: map the exact proposed deletion back to the raw ASR source, require the same repeated unit at the original positions and an explicit original clause boundary, and refuse to act if the alignment is ambiguous. The trace demonstrates why final merged text alone is insufficient: chunk joining removes the comma boundary before local review. A generic “noun-like unit” or proximity rule is not reliable enough to label intent; a clause-role heuristic would need carefully bounded patterns and contrast probes, including the real-stutter example, before use. Prefer a conservative rule that can miss cases to a broad rule that preserves all comma repetitions.

Do not roll back entity or ITN changes when restoring a repetition. Require the unit being restored to match the source and surviving output exactly after only punctuation/space handling; reject restoration if the changed span overlaps a numeric normalization, entity patch, or other substitution. Insert only the missing source-owned copy and separator, retaining unrelated Refiner edits. Deterministic cleanup must run after insertion with the source-preservation guard enabled.

Cache and context constraints: intermediate local-review results are attached to source spans by `_reviewed_source_spans` and copied into fixed-group cache only when each span's `source_text` exactly equals the cached source group. Keep that exact-source check. Do not write a whole-utterance final restoration into a differently partitioned window cache; the existing final path intentionally replaces `refinement_source_spans` only for the final display ownership. Any new repair record/cache key should include the original source span (or its hash), candidate source/target, and the group/context revision. A context-only match can reuse a KEEP/REMOVE decision against a different source boundary and is unsafe here. Preserve source offsets through punctuation stripping/normalization rather than calculating them in the merged display text.

## Frozen source-clause guard review

I reviewed the frozen snapshot under `runtime/frozen/system/`, whose `patch_manifest.json` records the changed `repetition_preservation.py` and `web_app.py` hashes. The source analysis is warmed once at app startup and uses an isolated Jieba POS tokenizer. The new cross-clause predicate requires an original punctuation separator, a repeated unit tagged wholly nominal, a preceding lexical verb, and a following verb/adjective predicate. The new tests explicitly cover `索引`/`名单` object-to-topic reuse, several positive predicate variants, and contrast cases including the real stutter `接着确认，确认货位`; they also verify a cached REMOVE is intercepted before neural review and test restoration alongside entity and numeric edits.

This is a bounded POS-and-pattern safeguard, not a semantic intent classifier or dependency parse. POS segmentation errors can still cause both missed protection and false protection; in particular, a genuine noun stutter that happens to fit the same object/topic shape may be retained. Conversely, non-noun repetitions and clauses without a punctuation mark or recognized predicate remain outside the rule. The behavior is therefore suitable to describe as a conservative text safety rule only. The final restoration inserts only aligned source-owned repetitions/separators and does not write a whole-source repair into a different group cache. Candidate row indices and absolute parquet paths are recorded in `source_candidates.json`.
