# Refiner 窗口输出核验计划

本文件只整理 `all_refine` 第 0 轮的 16 个固定 K=3 窗口。统计为 5 个 accepted 且输出等于 baseline、7 个 accepted 且改写、4 个拒绝并回退。另有 2 个窗口的每次原始模型调用 input/output 完全相同；这是与上述分类重叠的子统计，不另加到窗口总数。

7 个 accepted 改写和 4 个拒绝都尚未听音核验。自动接受只表示现有精修保护流程接受了候选，不能说明改写正确或有益。

其中高分窗口也会触发改写；低分窗口也可能被 Refiner 原样接受。ASR token 分数描述识别 token 的模型分数，Refiner 决定是否改写及现有完整性保护接受与否是不同信号；分数未校准，不能据此判断重复或填充词该删还是该留。

## 下一步

优先对这 7 个 accepted 改写和 4 个拒绝窗口回听原音，人工记录目标文本、编辑任务/位置，并判断历史精修相对 ASR 文本是有帮助、中性、有害还是无法判断。三个原音合计约 100.848 秒；窗口对应源片段边界，但不保证能按自动文本边界逐字定位。本文没有听音，不包含人工金标。

在完成音频核验前，不用这些窗口训练模型、不据此调门控阈值、不声称精修质量收益，也不把 Refiner 输出或自动保护器结果当作 gold。
