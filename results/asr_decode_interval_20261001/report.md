# 文件转录 ASR 解码间隔对照测试

测试日期：2026-10-01。数字规则库开启，最终精修关闭。

测试音频：测试音频 4（中国地图），724.437 秒；输入文件 `/tmp/audiocpp-native-benchmark-inputs-20260929/test4.wav`。

只调整模型解码间隔，其他设置不变：同一 Qwen3-ASR-1.7B / vLLM、Silero VAD、GPU、Web 精修设置，上传均为 1 秒 PCM 块（725 块），离线流式发送，不按音频时长实时等待。ASR 内部送入 streaming_transcribe 的聚合间隔仍为 0.5 秒。

## 结果

| 指标 | 1 秒（暖机后复测） | 2 秒 |
| --- | ---: | ---: |
| 完整转录到最终输出 | 77.011 秒 | 59.540 秒 |
| 音频发送及逐块确认完成 | 75.421 秒 | 56.976 秒 |
| 发送完后等待收尾 | 1.590 秒 | 2.563 秒 |
| ASR 模型耗时累计 | 56.614 秒 | 40.314 秒 |
| VAD 耗时累计 | 6.478 秒 | 6.321 秒 |
| ASR 文本更新次数 | 660 | 349 |
| 首次文本（加速上传墙钟时间） | 0.235 秒，第 3 块 | 0.282 秒，第 4 块 |

总耗时减少 17.471 秒（22.7%）；模型耗时减少约 28.8%。代价是文件转录的原始文本更新粒度变粗。首字墙钟时间来自加速上传，不能等同于实时麦克风首字延迟。

测试顺序为 1 秒 → 2 秒 → 1 秒。最初 1 秒运行耗时 90.099 秒，包含启动暖机影响，未用于上述收益计算。三次均未检测到其他转录会话并发。

## 文字质量检查

暖机后 1 秒结果与 2 秒结果：精修文本字符相似度约 99.8%；去掉 Unicode 标点及空白后，文本完全一致。原始及精修文本的数字校验器提取的数值序列均一致。未发现整句丢失或新的精修文字改写。

差异主要为逗号删除、句号与逗号替换、破折号、问号。例如“但70公里，在中国大地上”变为“但70公里在中国大地上”，“源源不断地汇入黄河。让黄河”变为“源源不断地汇入黄河，让黄河”。这些标点差异仍需人工按听感判断，不能保证所有断句均正确。

原始转录另有“遍布全舰”→“遍布全线”的变化，以及中文年份→阿拉伯数字的等值变化；精修后非标点内容一致。没有人工标注参考文本，本测试不能证明整体识别准确率不变，也不能推广到所有音频。

## 保留范围

保留 2 秒设置，仅用于网页文件上传；麦克风不传覆盖参数，沿用服务默认 1 秒解码。未调整精修门控、数字规则、模型提示词、VAD 参数或 1 秒上传块大小。

当前 ASR API `/stream/start` 支持可选 `chunk_seconds`；WebSocket 将 `asr_chunk_seconds` 透传为会话配置，不传则保持服务默认。Web 页面文件入口请求 2 秒，麦克风入口保持默认。
