# 简化提示词后的第二轮真实生成检查

## 结论

固定开发例句改善，自动生成样本仍不适合直接进入正式训练。当前提示词调整不足以解决所有问题。

| 项目 | 第一轮 | 第二轮 |
| --- | ---: | ---: |
| 固定例句原始标签符合任务要求 | 12/16 | 16/16 |
| 固定例句被配对硬校验接收 | 16/16 | 15/16 |
| 自动 Oral 请求 | 24 | 24 |
| 有效 Oral | 24 | 23 |
| 有效 Oral 字符数中位数 | 269.5 | 103 |
| 有效 Oral 超过200字 | 20 | 2 |
| 流程导出 SFT 候选 | 11 | 8 |

第二轮8条候选的主代理逐条复核结果为：2条暂未发现问题，5条有明确问题，1条存在歧义。候选通过当前自动 QC 不等于标签质量合格。

## 执行方式

- 同一本地 Qwen3-30B-A3B-Instruct-2507 4bit 教师模型、单张 RTX 3090、vLLM 0.17.1，接口 `http://127.0.0.1:8010/v1`、模型名 `refiner-teacher`。
- 复用第一轮的三个场景种子池和相同控制随机种子，重新生成全部固定检查和自动口语／目标文本。第一轮文件没有覆盖。
- 三个场景为日常聊天、编程和解释说明，每场景请求8条。未覆盖其余六个场景。
- 固定16条只作诊断，不混入训练候选。它们与提示词示例有重合，分数不能当作独立测试集准确率。
- 生成文本具有随机性；本次同时改变了生成、精修、质检和ASR提示，因此不能把差异全部归因于删除某一句保护要求。
- 本轮复用了种子，没有重新检验种子提示的改变。生产 pipeline 代码没有在运行中继续修改，没有训练学生模型。

## 改善的具体例子

```text

第一轮：预算是300元，不对，预算改成500元。

输入：收件人是钟宁，钟表的钟，宁静的宁。
```

星期改口也已生成正确原始目标“最后定周三开会。”，但未修改的数字字面校验依然拒收，导致实际配对接收15/16。

## 仍然存在的问题

### 质检仍有漏判及错误理由

另给新版质检8个固定对照：上一轮4个错误标签、各自4个正确标签。新版拒绝3/4错误标签，接收4/4正确标签。未清理的“红色→蓝色→红色”仍被放行，理由声称蓝色已删除，但目标中实际仍有蓝色。见 `qc_controls.json`。

自动生成候选中也有类似错误：

- `auto_explanation_02`：保留“小加米”拼字提示和李娜、九寨沟、格力、耐克等不相关候选，QC仍放行。
- `auto_explanation_04`：把输入的拼读“G-D-W”写成“简称G-D-W”，把识别提示变成没有充分依据的简称断言。
- `auto_explanation_07`：保留与“支付宝”相冲突的拼音和“保障福”提示，QC还声称张晓峰、华为和星巴克已移除，实际仍在目标中。
- `auto_explanation_08`：保留“念作…”及“南／难”纯拼字说明，清理不完整。
- `auto_daily_chat_02`：仍有奶茶／咖啡话题串接，目标还增加了明确的“买”动作。
- `auto_daily_chat_03`：原样保留“之前说六点、现在改回七点”，真实历史和当前改口的边界不清，暂标歧义；QC理由“六点已删除”与实际文本不符。

### 硬校验仍可能误拦

23条有效 Oral 中，只有8条 Clean 被硬校验接收，另外15条触发数字或英文检查：7条数字、12条英文，原因可重叠。部分为真实改写，部分可能是正常去重复或删除拼字说明被误拦，不能把这15条全部归为教师错误。

编程场景8条本轮均被硬校验拒收。例如把 `null pointer exception` 改成 `NullPointerException` 是实际改写；另外也有重复英文词删除后词面序列不一致的情况。详见 `rejection_analysis.json`，应逐项修正规则边界。

### 一条口语生成重复失控

`daily_chat_6`重复“真香”“停顿”等直到4096 token输出上限，未形成完整JSON，按失败记录拒收。其余有效Oral仍有2条超过提示词200字要求。

### 覆盖与长度限制

本轮随机样本没有最终ASR截断配对，也没有抽到直通控制或single改口控制；相应能力只能参考固定检查，不能据此评价整条ASR模拟分支。

8条导出候选按教师tokenizer计算system/human/gpt原始文本token和最大368，没有超过1024；未加聊天模板，不是学生tokenizer的最终训练长度。

## 文件

- `comparison_summary.json`：两轮对照统计。
- `diagnostic_comparison.json`：16条固定输入、两轮原始标签、硬校验状态。
- `qc_controls.json`：4个错误、4个正确标签的质检结果。
- `candidate_adjudication.json`：主代理最终复核，2 pass / 5 fail / 1 uncertain。
- `manual_candidate_review.json`：先行复核记录；其中部分pass判定未考虑完整清理要求，已由主代理裁决文件纠正，保留以供追溯。
- `pairs_review.md`：每条实际输入、教师原始标签、配对校验及QC结果。
- `rejection_analysis.json`：15条自动Clean拒收记录及原因。
- `final/train.jsonl`、`final/pilot_sft.json`：当前流程导出的8条候选，包含已确认问题，不要直接作为合格训练集。
- `api_calls.jsonl`：实际模型请求／回答，包含未完成JSON的重复输出。
- `source_snapshot/`、`provenance.json`、`comparison_plan.json`：本轮代码快照、来源与对比边界。

后续需要处理自动源文本质量、数字／实体校验误拦和质检漏判，再做独立新样本检查。小批开发结果不能保证学生训练后的效果。
