# Luna audit — linear gate holdout sources

Read-only source and provenance review. No model, ASR, or service was started by this audit; only hashes, transcripts, and existing result metadata were read.

## Candidate pools already on disk

The AISHELL staging pool contains 6,848 aligned AISHELL-1 test recordings after excluding 328 recordings previously used when the staging pool was created. It is no longer a safe fresh test pool: a local ASR benchmark parquet contains 6,920 AISHELL-test rows. Against staging, 6,448 recordings have exact source-WAV/PCM16 hashes in that benchmark and 6,616 have normalized reference matches. The large-entity full evaluation used another 2,131 AISHELL-test recordings, including 80 not linked by those benchmark hash/reference matches. Although 152 staging IDs remain unmatched by those exact checks, the benchmark inputs do not preserve AISHELL recording IDs for all rows; do not claim those residual test-split entries are untouched without a source-ID mapping.

The SpeechIO source directory has six parquet shards and 12,254 unique `segment_id` rows. I scanned project ASR/benchmark JSON and JSONL records carrying source IDs, references, and hashes, as well as project CSV outputs. This identified 317 source IDs with prior project result use; exact whitespace-normalized source references matched those same used IDs and no additional unused IDs. The remaining 11,937 source IDs had no exact ID or reference match in the scanned project results. Remaining counts by shard are `ZH00000: 812`, `ZH00002: 2,979`, `ZH00005: 3,118`, `ZH00010: 2,204`, `ZH00011: 928`, and `ZH00024: 1,896`. These are candidate recordings with source-provided transcripts; they are not independently human-audited here. Any later sampling should use a fixed hash seed across shards/speakers and must not use ASR output quality.

## Frozen AISHELL-dev and synthetic sources

The current `human_sources.jsonl` contains 24 unique AISHELL-1 **dev** recordings from 24 distinct speakers. All WAV paths exist, each WAV SHA-256 matches the source file, and every reference exactly matches the official AISHELL transcript after removing the transcript's token whitespace. The official transcript file hash matches the manifest. None of the 24 recording IDs or audio hashes appears in the 103 prior AISHELL-result files listed and hashed by the manifest. The references have no exact normalized match in the prior gate text files or project benchmark output references. The full benchmark audio input is AISHELL test, not this dev split.

The references do exist in the project's `entity_library_20261003/source/aishell_ner_transcript.txt` annotation source. That file is a prior text/NER source, not evidence that these recordings were ASR-evaluated; describe the WAVs as unused in project ASR/benchmark outputs, not as text never seen anywhere in project sources. The manifest correctly says `ASR_pretraining_overlap_unknown: true`. The references are official corpus transcripts; no one audited these clips by listening (`audio_script_verified: false`).

The synthetic controls comprise 24 scripts across 12 template families, and an independent delexicalized comparison found zero overlap with the 10 prior `texts.jsonl` sources. They remain synthetic-script proxies, not human gold.

The superseded speaker-order preparation overlaps 15 of the current 24 AISHELL recording IDs. Its directory contains only its old source list, runtime snapshot, and transport-check log; it has no synthesized TTS audio or test ASR/streaming outputs. The current generator explicitly skips that unused preparation while collecting prior IDs. Count each current recording once; do not present the superseded list as a separate evaluation.

At source audit time, `audio_job_state.json` showed TTS complete with no test ASR yet. The actual paced WebSocket/HTTP-ASR comparison has since completed for 192 sessions; its read-only audit follows.


## Paced WebSocket and HTTP-ASR holdout comparison

The completed run contains 192 sessions: 24 AISHELL-dev official-reference clips and 24 synthetic TTS controls, each run twice under each policy. The primary `terminal_quality` model and 0.8 threshold were frozen before audio; model and Refiner weight hashes are recorded in the replay configuration. Refiner, MLM, classifier, and ASR were warmed on old train fixtures. The execution log and `streaming/job_state.json` reach 48/48 clips per repetition and 192/192 sessions; the test is marked consumed. The per-clip policy order reverses on the second repetition (48/48 clips). PCM and audio hashes match across all four runs of every clip, all sent chunks received acknowledgments, maximum in-flight chunks was 2, and there were no ASR/Refiner failures or timeouts.

For the 96 current/learned policy pairs, final normalized CER and exact-script counts were equal: 76/96 normalized exact sessions and CER 0.02136 for each policy. The human-reference subset had 40/48 normalized exact and 34/48 lexical exact per policy (normalized CER 0.02077, lexical CER 0.07602); the synthetic subset had 36/48 exact and CER 0.02184 per policy. These are separate measures: normalization can conceal lexical number/punctuation differences. References for human speech are the AISHELL official transcripts, but no one listened to these recordings during this audit. Synthetic scripts are not audio-verified.

There was one policy-pair ASR/final-string mismatch among 96 human pairs and none among synthetic pairs. On `BAC009S0735W0152` repetition 0, the same PCM yielded raw `杨棋…` versus `杨岐…`; both sessions had zero gate calls, zero Refiner calls, and normalized distance 1. This is ASR variation, not evidence of a gate effect. Transcript hypothesis histories matched in only 43/48 human pairs and 47/48 synthetic pairs, even when final text matched; paired latency should be interpreted with this ASR variability in mind. Learned output was neither better nor worse by normalized reference distance in any pair.

The learned policy made 24 window-gate calls across its 96 sessions: 14 retained the native Refiner call and 10 vetoed it. Total Refiner calls were 42 under current and 34 under learned; Plausibility calls were 2 each. Classifier scoring took 34.995 ms total over 24 calls (mean 1.458 ms, p95 1.661 ms, max 2.741 ms). This is callback scoring time inside this run, not a production service benchmark.

Across sessions, completion lag from the audio clock had p50/p95/max 0.191/0.547/0.617 s for current and 0.182/0.497/0.599 s for learned. Finish-tail maxima were 0.616 s and 0.597 s. Send-overrun maxima were 3.1 ms and 1.8 ms; backpressure stayed below 1 ms, with all chunk ACKs received. The local run uses paced 0.5-second packets, warmed models, and shared hardware; these measurements do not establish production latency or real-world generalization. A template/speaker-block bootstrap reports learned-minus-current lag of +0.009 s [−0.004, 0.021] for human speech and −0.091 s [−0.186, −0.008] for synthetic controls; the latter is based on only 12 synthetic template blocks and should be treated as a small-sample diagnostic.

### Repetition-preservation findings

Two synthetic multi-window scripts repeatedly lost a second noun repetition under both policies and both repetitions, through the unchanged local review path. In `_021`, raw ASR retained `检查索引，索引交给值班员`, but the final output dropped the second `索引`; the local candidate `索引索引` received `REMOVE`. In `_022`, raw retained `核对名单，名单送到调度室`, but final dropped the second `名单`; local candidate `名单名单` also received `REMOVE`. Each output was two normalized characters from its unverified script. The explicitly cued earlier repetitions (`归档结束` and `现场清空`) were retained; the adjacent noun repetitions were not recognized as separately intended. This is a reproducible local-review preservation limitation, independent of the learned gate, not a basis for adjusting the frozen threshold.

Other preservation controls behaved as scripted: `_018` kept `很重要，很重要`, `_019` kept `一张一张` but the ASR omitted `地` (distance 1), and `_020` kept `等等等等` with its verbatim-transcription cue. No claim is made that the generated audio was heard or that script mismatches are verified acoustic errors.

The holdout is now consumed and may be used only for regression. It reuses the AISHELL-dev source annotation text noted above, and whether the underlying ASR/Refiner pretraining included AISHELL remains unknown. The comparison is a small downstream heldout diagnostic, not an independent model-pretraining test or production deployment result.
