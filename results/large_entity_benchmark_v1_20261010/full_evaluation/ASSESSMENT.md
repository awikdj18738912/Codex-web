# 千实体库全量评估结论

全量已完成：1,346 个提前建库的标准名称，2,410 条真实音频，2,745 次标注目标提及，三组共 7,230 个唯一 Web 会话。三组共享每条音频同一次真实 ASR 初稿，使用冻结代码、相同精修门控与数字处理；参考仅用于预建词库和事后评分，不作为推理输入。

现有纯规则流程收益很小。加上词库候选引导的原音复核，有明确净收益，尤其在人名上；仍有误改，不能据此认定适合所有领域无审核自动使用。

|完整 Web 流程|目标字面命中|字面召回|字符错误率 CER|
|---|---:|---:|---:|
|无实体库|2,431/2,745|88.56%|2.71%|
|仅实体规则|2,433/2,745|88.63%|2.72%|
|实体规则＋原音复核|2,603/2,745|94.83%|2.16%|

完整原音方案相对无库增加 172 次目标命中，字面召回提高 6.27 个百分点；CER 从 1,077 个错误降至 859 个，相对减少 20.24%。相对仅规则新增 170 次命中，无已有目标命中丢失；172 条输出发生变化，其中 167 条字符错误减少、3 条增加、2 条错误量相同。

仅规则相对无库改变 12 条：5 条字符错误减少，7 条增加；新增命中 2 次，但总字符错误增加 7 个。这里评估的是带词库的完整流程，不能把所有变化都解释成确定性替换动作。

## 不能只看 CER 的误改

原音模块实际应用 178 处修改，4 处目标名称不在给定参考里，其中 3 条导致完整流程 CER 退化。另一条虽然 CER 改善，实体身份仍与参考不符。

300 条无库目标负例中有 1 条被改动并退化；负例 CER 从 51/4,219（1.21%）变成 52/4,219（1.23%）。原音重识别看到了候选词后仍可能产生错误确认，尤其是两字近音词。上下文锚点吻合也不能单独证明实体身份。

这些结论来自参考字面比较，未逐条人工听审。标准名称按字形去重，未完成真实世界身份链接或全面别名消歧，不能把字面召回解释成完整语义实体识别正确率。

## 精修与开销

原音复核进入 Web 后续处理前，命中 2,604/2,745、CER 2.06%；完整流程后命中 2,603/2,745、CER 2.16%。现有 Web 处理包含精修、数字规范和重复处理，差异不能全部归因于精修模型。三个条件均有 3 次原本正确的目标字面命中在后续处理中丢失；带库条件另恢复 2 次。

2,410 次初稿识别之外，触发 2,061 次带候选词的真实原音重识别，172 条实际改字。复核调用率 85.52%，发生改字的比例约为复核次数的 8.35%。大库下无效复核开销仍明显。四并发 HTTP 请求时间不能用于宣称单用户延迟或转录提速。

独立方法日志捕获的是 refine* 文本精修：三组 111/278/187，共 576 次。Web 累计逻辑调用还包括重复审核：265/430/340，共 1,035 次。重复审核有单独 review_* 方法，因此两种统计口径不同；会话计数也不是 GPU forward 次数。报告已区分这些口径，没有改动推理结果来对齐计数。

## 后续方向与本轮处理

保留当前原音复核方案，作为有明确净收益但仍需审计的辅助功能。下一轮优化应只涉及实体模块，优先验证候选间竞争与拒绝条件，减少两字同音误确认和大库无效重识别；也可在实体后处理内检查已经确认的词是否被后续流程改坏。不能直接靠提高一个分数门槛保证这些问题解决。

本轮测试集已经用于诊断，后续若用它调参，应另外冻结验证集合，再比较新增命中、丢失命中、负例误改和调用开销。未按效果删样本，未针对上述名字添加特例或错误别名，也未为取得更高分修改实体以外的代码。

正式用户词库未被覆盖。冻结数据、实验词库和代码快照哈希一致；8051、8081、8766 服务均健康，备用 8081 已恢复。采集曾在 2,074 条处遇到服务中断并续跑，恢复健康配置一致；每条音频的三个条件仍使用相同初稿，不能将本轮当作连续运行稳定性测试。
