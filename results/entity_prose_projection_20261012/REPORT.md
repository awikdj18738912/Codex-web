# 有边界的精修正文实体修正

2026-10-12。仅修改 `system/entity_pipeline.py`，新增 `system/entity_prose_projection.py`；没有修改 Web、精修模型、数字处理、门控或原音复核代码，也没有添加错误别名。

问题：最新 trace `bb3740bf411e4b01835c264751d66157` 已检出厉飞羽→厉飞宇，但旧规则要求结构化实体补丁。模型返回正文，并删了“在”字，整窗因此被拒绝，正确的实体改动一并丢失。

新规则只将实体改字应用到原句。必须是登记库的 HINT_ONLY 候选、同长度3–12字、匹配器拼音相似度1、仅一字不同、源与目标位置唯一、无低候选间距，且正文与实体替换后的原句词法内容相同，或仅在实体外少一个字。至少保留8个实体外词法字符。标点和其他文字全部采用原句。显式补丁继续走原规则；保留策略、PERSON/ORG高风险类型、KEEP_RAW、弱或多重候选不放行。只在正文确认，复制的 `<KEY>` 不算证据；占位符仍须通过现有还原校验。

`entity_type_not_auto` 限制匹配器直接自动替换；这条规则是模型正文确认，与既有结构化补丁采用同一保留／高风险检查，并重新运行实体与内容校验。不会把 LOC 等非高风险类型一概改为匹配器自动替换。
