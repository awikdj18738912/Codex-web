# 学习型门控编码器 CPU 开销实测

日期：2026-10-09。

本机的轻量编码器在双线程、单请求条件下，64／128／256／512 tokens 的中位耗时分别为 8.8／13.1／21.2／42.1 ms。当前正则门控已经跳过很多精修，新门控不一定缩短整段转录时间；尤其在精修调用稀少的材料上，评分开销可能超过节省的精修成本。

## 测量范围

- 本地 `models/entity_ranker/encoder`，4 层、256 维 BERT 编码器，8,765,696 参数；追加未训练、仅用于计时的 MLP 三分类头。
- CPU：AMD EPYC 7H12；当前环境暴露 36 个逻辑 CPU。
- float32；PyTorch 2.11.0+cu130；实际运行在 CPU，没有调用 CUDA、ASR 或 Refiner。
- 每项预热 5 次、测量 30 次。表中包含 tokenizer、CPU tensor 构造、编码器、简化分类头及 softmax。
- 输入为合成中文文本，按指定长度 padding；未测真实门控特征抽取、生产并发、排队或门控准确率。
- 编码器和 tokenizer 加载约 413 ms；是启动成本，未包含在每次请求耗时中，也不应逐请求重新加载。

## 单请求结果

| 输入长度 | 单线程 p50 | 单线程 p95 | 双线程 p50 | 双线程 p95 |
| --- | ---: | ---: | ---: | ---: |
| 64 tokens | 10.80 ms | 10.98 ms | 8.84 ms | 9.20 ms |
| 128 tokens | 17.76 ms | 18.20 ms | 13.07 ms | 13.43 ms |
| 256 tokens | 33.74 ms | 34.27 ms | 21.24 ms | 21.52 ms |
| 512 tokens | 73.23 ms | 73.65 ms | 42.13 ms | 42.30 ms |

批量 4 条、双线程、256 tokens 时，整批均值为 68.22 ms，均摊每条约 17.06 ms；这改善吞吐，但整批 p95 为 71.59 ms，不能称为每条在线延迟 17 ms。可以批处理已就绪的多个局部复核候选，不应为了凑批而等待后续音频。

## 何时能抵消评分成本

粗略计算条件：

```text
门控新增计算时间 ≈ 门控缓存未命中数 × 平均门控耗时
节省精修计算时间 ≈ 减少的调用数 × 对应任务平均调用成本
```

这比较的是累计计算开销，不是端到端墙钟。CPU、ASR 和 Refiner 可能并行，资源竞争和关键路径仍需完整音频试验。

对照 2026-10-03 的已有记录：

| 音频 | 时长 | 总会话耗时 | Refiner 逻辑调用 | 调用墙钟累计 | 每次逻辑调用均值 | 最终窗口门控记录 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 测试音频4 | 724.44 s | 54.22 s | 16 | 3.968 s | 248.0 ms | 83 |
| 测试音频5 | 843.26 s | 80.70 s | 158 | 42.601 s | 269.6 ms | 156 |

日志中的逻辑调用包含不同任务，均值不能当作所有生成和复核任务的固定成本。最终门控记录也不代表真实新增编码器调用次数；有缓存、重复检查及局部复核，所以以下只作量级估算。

假设音频4的 83 个窗口全部按 256 tokens、双线程重新评分：

```text
新增窗口评分：83 × 21.278 ms ≈ 1.766 s
抵消所需调用减少：ceil(1766 / 248) = 8 次
只减少 20% 的 16 次调用：约节省 0.794 s，低于上述评分成本
```

该估算尚未加入局部复核门控、真实特征抽取和并发影响。因此不能据此宣布新门控能提速。音频5存在更多精修调用，潜在节省空间更大，但也有更多局部复核与上下文评分，需逐任务计账。

## 对方案的调整

1. 使用实际输入长度动态 padding，不把 512 上限当作每次固定编码长度。默认争取将完整目标及必要上下文控制在 256 tokens；超长目标保持完整，显式计入长输入档位。
2. 模型启动时加载一次。按实际有效输入和版本缓存决策；相同局部上下文可复用编码表示。
3. 神经门控只评估新完整窗口／未缓存的就绪候选；不对每个 PCM 块或累计 ASR 更新重算。
4. 两线程只是本次微基准更快的配置；正式环境仍需核验它是否影响 VAD 和 HTTP 工作线程。
5. 上线目标改为“总成本扣除路由器开销后仍有净收益”，调用下降 20% 不再单独构成通过条件。实际墙钟结果必须另做同机、同音频、暖机后的交替对照。
