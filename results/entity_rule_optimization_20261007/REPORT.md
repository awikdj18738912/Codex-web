# 实体替换规则优化：可选的长术语内部漏字补全

2026-10-07。**保留一项小范围有效的优化：对明确开启选项的长术语，允许补全一个满足严格约束的内部漏字。实测新增修复 1 个已见真人音频版本，其余回归输入没有新增变化。收益有限，不能称为通用医疗纠错或明显整体提升。**

## 原规则的限制

已有语境拼写规范要求标准名与源文字字数、完整拼音都一致。即使登记了“骨质疏松症”，原始转写“骨疏松症”也不能直接纠正。

本轮没有放宽全局相似度阈值，没有自动替换另一合法疾病，也没有根据测试错误添加永久别名。新增补全作为独立权限 `allow_internal_omission`，默认关闭，旧语境配置继续保持原先的同音规范范围。

## 保留的规则

同时满足以下条件才允许补全：

1. 已登记、启用、normalize 策略的 TERM，标准名为 5–16 个汉字，并明确开启内部漏字补全。
2. 标准名同时存在于独立分词词典；源写法不是该词典中的完整词。实体候选不会被加入这个词典来证明自己正确。
3. 只缺一个内部字，其余字完全相同；首字和最后两字不变，不补数字、否定、方位等限定字。
4. 插入位置不能切开原文已有词，不能跨标点或覆盖已保护实体；标识符和拼写讨论位置保留。
5. 当前实体库中只有一个标准名称对应这个漏字形式，并且源句满足词条配置的语境要求。

成功记录为 `CONTEXT_OMISSION`，仅替换该实体跨度。后续精修失败时保留这项已通过规则检查的规范，不接受模型对其他内容的自由改写。

这条规则不支持“Tevi→TAVI”、任意首尾漏字、任意近音、姓名补字或两个以上缺字。词典、边界或语境证据不足时仍保留原文。

## 对照与结果

修改前保存旧实现的输出，再用相同输入、标准名和语境配置运行新实现。实验对长医学术语统一加入“患者、医生、检查、手术、症状、治疗、疾病、服用、开刀”等通用语境词，**基线与新实现使用完全相同的词条和语境**。因此新增收益来自补全规则；不能说上一轮未包含这些语境词的配置已经自动获得相同收益。

最终开关版本的比较结果：

| 回归材料 | 输入数 | 新增修复 | 新增退化 |
|---|---:|---:|---:|
| 三个医疗场景的已保存真实 ASR 输出 | 168 | 1 | 0 |
| 原有医疗真人音频 ASR 输出 | 430 | 0 | 0 |
| 正确医学文本回归 | 1,000 | 0 | 0 |
| 药名 TTS 的 ASR 输出 | 96 | 0 | 0 |
| 新闻姓名真人音频 ASR 输出 | 427 | 0 | 0 |
| 合计 | **2,121** | **1** | **0** |

这些输入包括同一录音的噪声变体及文字材料，不能称为 2,121 条独立真人录音。全部沿用已保存的开发／回归材料，未作为新的盲测集。医学字幕也存在省略与口语差异。

唯一新增修改是 `MultiMed_Chinese_train_0579` 原音版本：

> 基线：……发现他们其实有**骨疏松症**，所以很多患者可能自己都不知道……
>
> 新规则：……发现他们其实有**骨质疏松症**，所以很多患者可能自己都不知道……

只补入“质”，句子其他文字完全相同；原有“查觉”等一般文字问题没有被这项规则改写。词条仍是标准名称“骨质疏松症”，没有录入“骨疏松症”错字别名。

## 完整精修流程复现

选取上述正例及另外两条骨科录音的原音／噪声版本，完成 6 次新的实际 ASR 解码。随后把每份真实 ASR 分块响应相同地回放进当前 WebSocket 处理器，使用真实本地 GPU Refiner，对比补全分支关闭与开启。

- 共 12 次完整 Web 回放、19 次真实 Refiner 方法调用。
- 两组词库、语境、ASR 输出、精修参数及数字规则相同，唯一差别是新增补全分支是否执行。
- 6 对比较中 1 对改善、0 对退化，复现的是同一个真实音频正例，不是另一个独立收益样本。
- 无匹配语境的漏字例，以及另一合法疾病写法，不执行补全。

数据见 `web_replay_opt_in/` 与 `web_summary.json`。此部分是固定真实 ASR 响应的质量验证，不是实时麦克风延迟测试。

## 配置和兼容性

新选项按词条开启。旧库读取不会增加字段或启用新行为；首次明确启用时才在语境表增加对应字段。默认关闭，关闭语境、preserve、禁用词条、非 auto 模式和不允许自动规范的调用仍不能补全。

CLI 可使用 `enable --allow-internal-omission`；JSON 导入在 `spelling_context` 内设置 `"allow_internal_omission": true`。新增字段校验、保存、导出、关闭、原子导入以及旧库读取均有测试。

`orthopedics_opt_in.json` 为本轮可复现配置包，包含标准名、统一语境和显式补全权限，可通过实体模块现有导入命令加载到测试库。**正式实体数据库未导入此包，也未开启新选项；运行中的服务未重启。**使用新规则需要加载更新后的实体模块，并对相应词条显式启用。

详细启用方法见 `system/ENTITY_SPELLING_CONTEXT.md`。
