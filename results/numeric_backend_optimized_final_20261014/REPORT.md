# 数字精修优化验收（2026-10-14）

已修改项目源码，运行中 Web 服务尚未重启，需重新加载进程后生效。

## 实现

- 数字完整性失败且没有实体占位符故障时直接采用原有安全回退，省去模型重试；其它完整性重试保留。
- 门控只忽略完整落在 zh-itn 实际转换来源范围内的短语/字符重复。电话号码里的重复数位不触发模型；号码外口吃和整句数字复述仍检测。
- 在数字数值和后续完整性校验之前，将等值冒号时刻恢复为来源时刻写法。时/分/秒必须相同，不能修复真实改值或丢秒。
- 哦不作为明确改口标记进入门控、窗口合并与校验。整点改口为时分时，只在明确时刻语境及匹配的最终时刻下允许删除旧整点。
- 没有冒号候选的窗口直接跳过新时刻解析；数字校验保持启用。

## 验证

- 225 项门控、数值保护、窗口、Web 完成路径和上下文回归测试通过。
- 24 个匹配文本窗口（12 纯数字、12 数字混合清理），每个策略 3 轮，共 144 条计时观测。共享同一个已预热本地 Refiner，RTX 3090，CPU 2 线程，交错策略顺序并同步 CUDA。
- 测量不含 ASR、模型加载、上传、WebSocket 调度或线上排队。实体数据库与学习门控关闭，使用同一原生 tri_state 门控。

| 类别 | 直接纯 Refiner 均值 ms | 优化后规则链路均值 ms | 纯模型调用 | 规则链路调用 | 规则链路重试 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 纯数字 | 443.53 | 6.80 | 36 | 0 | 0 |
| 数字 + 口语清理 | 402.32 | 378.68 | 36 | 36 | 0 |

混合组同轮平均耗时约减少 5.9%，但中位数为规则链路 368.5 ms、纯模型 344.0 ms，并非每句都更快。纯数字组跳过全部模型调用。第一轮完整 36 句四策略复测另存 ../numeric_backend_optimized_20261014；最终精简对照期间所记录源文件哈希没有变化。

与历史规则链路对比：72 条规则输出中 66 条相同，6 条变化来自两个时刻案例各三轮。以前拒绝时刻格式并回退，现在保留正确时刻和模型已完成的口语清理。混合组历史调用 45 次、重试 9 次，当前调用 36 次、重试 0 次；纯数字历史调用 3 次，当前 0 次。

电话复述的一个样本三轮均安全回退，保留了部分口语；其它数字改值、单位错误、删秒负例继续拒绝。没有独立人工质量准确率评分，有限回放不代表所有线上语境。
