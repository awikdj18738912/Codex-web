688 条受控窗口有 648 个不同的 baseline/target 配对，其中 466 条是 KEEP。它们来自原始合成脚本的训练分区，以及新增的 18 条明确说明上下文的虚构文本用例。

受控材料中的编辑操作覆盖六类：填充词 107、重复 107、自我纠正 2、局部错字 2、标点/误断句 2、实体纠正 2。后四类仅有少量任务定义，远不足以证明检测器能够泛化处理这些问题。KEEP 用例包含强调、否定、引用、逐张表达和跨分句的“名单/索引”衔接。

## 坐标与输入接口

每条记录保留规则处理前的 `raw_asr`、数字与实体准备后的 `baseline_text`、左右上下文、动态实体候选、实体提示和保护范围，以及源录音、原分区、模板组与窗口策略。

同生产 Web 使用 `fixed_k3_v1` 的标点块构造和 K=3 分组逻辑。对于 ASR 视图，优先沿用保存的 VAD 完成片段；不足 K 的组标为终态短组。这是固定源文本的数据整理，没有模拟全部在线修订与时序。

`edits` 使用 Python Unicode 字符坐标，区间为 `[start,end)`；输出 `DELETE_CANDIDATE / CORRECTION_CANDIDATE`，未修改字符标为 KEEP。插入使用源文本间隙坐标，例如末尾补句号不需要虚构一个源字符。

重复字可能存在两个同样可执行的删除位置：单个编辑会记录可等价重建目标的 `offset_alternatives`。多编辑样本未穷举对齐歧义，明确记为 `ambiguous_offsets=null`、`alignment_ambiguity_checked=false`；不能按唯一字符标签进行独立验收。

保护字段中的坐标属于其明确保存的 `itn_text`，不冒充实体替换后 baseline 的坐标；编辑标签始终属于 baseline。整段 baseline 上的窗口起止坐标也单独保存。

## 避免了哪些误标

- 合成脚本、ASR 输出和 Refiner 最终文本没有提升为人工音频金标。模型候选保留策略、轮次、源行与拒绝原因信息，仅用于核查。
- ASR 脚本投影只产生待核查候选，保留无关识别错误。没有把“脚本本来没有要清理的内容”解释成“ASR 全文没有错误”。脚本标点和实际说话意图仍待核查。
- 112 条纯数字格式、保留或上下文规则用例不作为精修正样本。3 条数字句子清理用例留在回归区，其中 2 条不能通过当前数字表面完整性检查，标为待核查；不会训练成任意改变数字值。
- 跨窗口编辑不能完整定位时，目标和编辑标签置为未确定，不能把两个半窗口标成 KEEP。本批有 4 个这样的待核查窗口。
- 原始合成 dev/test 不进入训练材料。已消费回放数据只进入 regression/review；即使以后核验，也不能自动变成新的独立验收集。
- 数字和明确别名先按规则处理，再生成标签，避免训练检测器重复执行规则库工作。

## 明确的数据缺口

当前真实音频的人工核验精修目标为 **0**。931 条 ASR 窗口中，脚本投影提出的主要任务仍是填充词与重复；现有资料不能支持错字、实体、标点和自我纠正的完整真实音频监督。

例如 ASR 中“贴贴”可以暴露漏检，但 Refiner 改成“贴压”不能作为正确目标。朗读逐字参考也不能直接当去口吃、去赘词的清理目标。单靠增加这批弱材料，不能保证小检测器与 Refiner 能力对齐。

下一步可用受控文本材料验证字符标签训练与推理成本，真实音频候选先旁路记录。启用实际跳过前仍需独立的应修错误召回、错误修改与整段完成时间验证。

## 验证与复现

13 项有针对性的测试通过：删除/插入/多编辑重建、重复坐标歧义、数字格式排除、规则拥有的数值保护、核查哈希过期、仅文本核查不产生音频金标、回归区不被提升为训练区，以及固定分组中的编辑归属。

全部 1,676 条记录检查了可用编辑的目标重建、字符标签长度、窗口坐标、核查依据哈希、训练资格与文件哈希；结果见 `integrity_check.json`。Luna 做了独立的只读数据来源和导出审查，指出的多编辑歧义状态已修正。

输出目录必须不存在。默认使用原 round4 训练来源、原始脚本训练分区、冻结实体库快照和当前 zh-itn。`manifest.json` 保存来源、规则库、代码与产物哈希；`executed_code/` 保存执行代码。此前 v1/v2 目录是中间版本，正式数据为本目录 v3。

如已取得逐条核查结果，可通过 `--reviews review_decisions.jsonl` 重新导出至新目录。每条需包含 `id`、`review_basis_sha256`、`reviewer`、`review_kind`、`audio_checked`、`desired_text` 和与实际编辑数量一致的 `edit_tasks`。

`assistant_text_only` 只产生辅助文本核查记录；`human_audio_cleaned` 需要录音来源及明确听核标记，且只允许原训练分区进入音频训练文件。上下文、实体候选、保护范围或文本变化会使旧核查哈希失效；目标还需通过规则拥有的数字表面检查。这是显式核查输入的验证接口，导出器不会代替人工听核，也不会自行填写人工标签。
