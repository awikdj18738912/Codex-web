教师服务与实际生成流程已跑通。当前标签生成和质检仍有已复现的问题，目录中的 SFT 是候选示例，不代表已经通过训练质量验收。

## 实际执行

本次调用当前生产生成器完成：教师生成种子 → 24 条 Oral → Clean → ASR 配对 → 组装 → 教师语义 QC → 去重 → SFT 导出。

测试场景为日常聊天、编程、解释说明，每类 8 条；没有覆盖全部九个场景。另有 16 条预先写好的固定输入，仅用于诊断，不进入自动生成训练对。原始模型回答、拒收记录和校验后标签分别保留。

长种子请求触发 180 秒超时后，保留完成的固定诊断与两个种子池，恢复运行时将请求超时设为 600 秒。解释说明场景的小批种子池使用每类 8 个条目；生产种子提示仍为每类 40 个。此次没有修改生产 pipeline 代码，没有启动学生训练。

## 已确认的问题

### 1. 标签清理不完整，语义 QC 仍放行

下列四个固定检查均未达到清理要求，而且都被当前语义 QC 放行：

| 输入 | 教师实际结果的问题 | 应有处理 |
| --- | --- | --- |
| 预算是300元，不对，预算改成500元。 | 整段改口原样保留 | 只保留最终预算500元；数字写法继续复制规则结果 |
| 我想用红色，改成蓝色，还是用红色吧。 | 回退过程全部保留 | 去掉已放弃的蓝色候选，保留最终红色 |
| 周一开会，不对周二，最后定周三开会。 | 只补标点，旧星期仍在 | 只保留最终周三开会 |
| 收件人是钟宁，钟表的钟，宁静的宁。 | 拼字提示原样保留 | 输出“收件人是钟宁。” |

硬校验主要保护数字和英文词面；当前语义 QC 接受“保留全部改口历史”的标签，因此它的通过数不能当作清理任务合格数。

自动样本中也能看到类似问题。例如 `auto_explanation_04` 仍保留大量解释性拼字和重复，`auto_explanation_07` 仍保留拼音、缩写提示。`auto_explanation_05` 的目标将源中的“好像是在优衣库工作过”变成“曾在优衣库工作过”，需要检查不确定性是否丢失。以上候选均被当前 QC 放行。

### 2. 数字校验误拦中文星期改口

直接调用当前 `lock_training_target`：

```text
输入：周一开会，不对周二，最后定周三开会。
正确候选：最后定周三开会。
校验结果：拒收。
```

中文数字字面保留检查没有识别这段明确放弃的旧星期。对照的“预算300元改成500元”正确候选能通过。详见 `numeric_guard_diagnostics.json`。

### 3. 口语样本自然度与长度

部分 Oral 将多地旅行、商品、编程术语等无关话题硬串在一起，并复制提示中的 PyTorch、GPT-4o 等示例名称。有一条误断句控制要求恰好一个错误句号，实际出现了两次“真。让我感到惊讶。”。正式生成前需要增加源样本质量检查。

11 条候选按教师 tokenizer 分别编码 system/human/gpt 后，三段 token 和为 402–1174，中位数 573，1 条超过 1024。这没有计算聊天模板，也不是学生 tokenizer 的最终长度；只能用来定位需要检查的长样本。

## 文件

- `pairs_review.md`：每条原始输入、规则后输入、教师原始标签、校验结果及最终候选。
- `summary.json`：流程统计及配置。
- `diagnostic_assessment.json`：16 条固定检查的任务判定。
- `fixed_checks.json`：原始固定检查结果；其中 accepted 仅表示通过配对硬检查。
- `rejection_analysis.json`：Clean 拒收原因分类与原文。
- `numeric_guard_diagnostics.json`：正确候选能否通过数字／实体校验的对照。
- `semantic_qc.jsonl`：当前 QC 的原始判定和理由。
- `length_review.json`：候选长度检查。
- `api_calls.jsonl`：所有实际模型调用的提示、回答及耗时，包含被中断请求的记录。
- `final/train.jsonl`、`final/pilot_sft.json`：11 条自动生成候选；不含固定诊断输入。
- `provenance.json`：关键源文件哈希与模型来源。
- `teacher_server.log`、`pilot_run.log`：服务和恢复运行日志。
