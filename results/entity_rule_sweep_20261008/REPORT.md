# 实体替换规则对照：2026-10-08

本轮比较 11 个配置（含现有规则），只保留有实际纠错收益的医学正式别称读音规则。**合计 208 个真人音频版本，库内名称保留 155/242 → 159/242；新增纠正 4 处，未观察到新增退化。**四处来自四个原始片段，全部属于 ECMO／ECMO手术这一组名称。提升约 1.65 个百分点，仍是局部收益，不能宣称找到适用于所有医学音频的最佳规则。

## 数据和对照方法

- 开发材料：上一轮 MultiMed 中文医疗真人音频 64 段、原音和固定 5 dB 白噪声共 128 个版本。词表沿用识别前从参考提取的 45 个标准名称及相同语境配置。
- 新批次：另选此前未解码的 40 段、共 80 个版本。选择时排除前三批 train 原始行，按固定种子选 12 段 ECMO、20 段其它词表内医学名称、8 段无词表名称的控制片段。原音、参考、音频路径及哈希见 `holdout/selection.json`、`holdout/asr.jsonl`。
- 正确文字控制：固定种子选取 1,000 条 CMeEE 训练标注文本，作为原样保持检查，不冒称为音频测试。
- 所有配置使用相同原始 ASR 输出。识别器没有接收逐条参考或领域词表提示。新增别称仅为 `ECMO → 艾克膜`、`ECMO手术 → 艾克膜手术`；没有加入“埃克莫”等错误写法。
- 名称及规则在检查新批次输出前冻结，见两个 `frozen_sweep_protocol*.json`。第二版来自旧材料和构造反例，第一版脚本未覆盖。接入时额外添加“人名”讨论的反例保护，没有利用新批次正确答案调节距离或分数。

音频及参考来自作者公开的 [MultiMed 数据集](https://huggingface.co/datasets/leduckhai/MultiMed)，医学文字控制来自 [CBLUE/CMeEE](https://github.com/CBLUEbenchmark/CBLUE)。正式别称有[中国疾控中心资料](https://tb.chinacdc.cn/jkjyzyk/twl/202103/W020210321669295949344.pdf)及[复旦大学 ECMO 设备采购文件](https://cz.fudan.edu.cn/cms/contentwh/download.htm?attachmentid=6f69d15bd11045568c9773f9f7d18de8)支持。“艾克膜手术”是登记的术式全称中将 ECMO 替为其等价别称。

### 额外开发探针：四个字全部识别错

新批次检查完成后，再做一个仅用于开发排错的探针：将最多三字不同改为最多四字不同，其余沿用 `sound_distance2_relaxed`。这组没有参与新音频验收，没有改变已选规则。

| 材料 | 输入数 | 新增改善 | 新增退化 | 决定 |
|---|---:|---:|---:|---|
| 开发音频和正确医学文字 | 1,128 | 0 | 0 | 无新增收益 |
| 构造的正常表达反例 | 2 | 0 | **2** | **否决，不接入** |

两个反例为“医生让孩子假装螃蟹练习动作”“医生用假装螃蟹这个例子说明表演技巧”。“医生”满足泛医学语境，但“假装螃蟹”仍是正常表达。宽松规则误改成“甲状旁腺”，说明完整近音加泛语境不足以证明实体身份。该反例是构造文字，不能计入真实音频退化数；结果和规则源码见 `whole_sound_probe.json`。

## 最终规则和使用方式

实体仍在转录前登记。除了标准名，可登记经审核的正式等价别称。新分支要求 `medical/TERM/normalize`、auto、允许自动规范，中文源跨度和别称为 3–16 字、长度及完整声母韵母相同，且当前标准名与别称空间没有另一同音目标。

只有紧邻“台／套／使用／启动／连接／上／做／接受／进行”等明确对象位置才继续验证。人物、作者、书名、标识符、拼写讨论及大多数独立词边界冲突拒绝执行。长短别称同时命中时，较长结果必须等于短名称规范结果加未变后缀，才整体优先。没有放宽一般拼音门槛，也不推断丢失音节、不同身体部位或另一合法诊断。

已接入 `CONTEXT_ALIAS_PINYIN` 修改记录及可信回退；后续精修失败仍保留这项已验证名称规范。建库资料来自公开来源，推理不联网。登记正式别称仍需审核，不自动抓取或推测。

可复用文件：`medical_entities.json`（45 标准名、2 正式别称及原语境）和 `official_alias_terms.db`。导入独立测试库，例如：

```bash
PYTHONPATH=. /home/aim0/anaconda3/bin/python -m system.entity_context_cli \
  --db /绝对路径/测试实体库.db import \
  --input /home/aim0/桌面/tan/ASR/Codex-web/results/entity_rule_sweep_20261008/medical_entities.json
```

新的会话选择医疗领域、normalize、auto；运行中的进程需要重新加载更新模块。正式用户库未自动导入这份词表，现有服务未重启。
