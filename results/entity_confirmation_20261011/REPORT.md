# 通用实体确认规则：实验与保留结果

保留一项小幅保护：很短的识别片段扩成更长的登记表面词时，必须有共享字形，或完整音节对应名称的开头/结尾。仍要求相同原音的复核输出和上下文锚点确认。登记短别名可以照常规范到较长的标准名。规则没有实体类型、领域或具体名称白名单，也没有增加 ASR 请求。

它挡住了“乐曲→越秀区”这种有害扩写，保留了“加喀→贾卡尔”等已验证的音节尾部补全。该句仍是“柏林乐曲博物馆”，给定参考为“柏林乐器博物馆”；本次没有恢复“乐器”，只避免进一步改坏。

原2,410条为进入Web精修前的原音复核指标：本轮只删除确认，172条旧修改全部检查为保留，原来未改字的录音不会产生新修改。没有重新声称完整2,410条Refiner实验。

第二批200条没有触发新的拒绝，结果一致主要证明兼容性，尚不能证明新场景的误改率已下降。其目标命中虽然达到182/182，仍有“庚阳→杨扬”“静秀区→越秀区”两处参考外的实体修改；字面目标满命中不等于整段文字或库外实体都正确。

新400条音频没有与原2,410条共享原始或解码PCM哈希，两批之间也去重。标准库仍是原1,346个名称，没有根据识别错误追加名称或别名。第一批含160正例、40负例；第二批150正例、50负例。来源为本地 AISHELL 和 Common Voice，沿用已知旧录音排除清单；不是说话人独立或模型预训练未见评估。

两批包含多个话题，分布和空缺保留在各自summary中。Common Voice标注主要为参考最长表面匹配，并非完整人工NER；部分词中表面匹配也不保证实体身份。第二批参考评分在第三版规则冻结之后进行，但其ASR已经采集，因此不将第三版描述为“在第二批ASR采集前冻结”的完全预注册实验。

## 实际Web和精修

5个诊断案例、10个成对Web会话实际加载现有Refiner，核对完全相同的PCM与真实ASR请求轨迹。案例包括本次扩写、历史“贾卡尔”补全、人名“杨德合”、医疗“水杨酸”和仍未解决的“中传”误改。

本次扩写在完整Web结果中被挡住，其余控制最终输出一致。首次集成测试没有正确替换Web处理器内部导入的基线类，导致基线断言失败；修正仅涉及实验注入，随后全部对照通过，生产Web代码未改。

最终24项实体测试通过，覆盖原音缓存、失败回退、同位锚点、短片段扩写、完整前后音节、显式别名和Web接入。曾用于被撤回规则的39项测试保留在实验档案，单元测试通过没有被当成真实音频有效的证据。

## 保留与上线

生产功能仅修改 [entity_audio_repair.py](/home/aim0/桌面/tan/ASR/Codex-web/system/entity_audio_repair.py)。新增状态标记 `short_expansion_rule=spelling_or_complete_edge_sound_v1`，用于核实服务已加载；它不改变确认逻辑。部署版除该状态标记外，模块AST与验证候选一致。

8051和8081按原启动参数依次重载，通过WebSocket ready核对新标记；ASR没有重启。正式用户实体库不被本实验替换，实验词库和冻结音频不变。本轮期间另有Web与重复处理文件变化，这些不是本任务的编辑，没有回退或覆盖。

这是减少一类有害扩写的小修正，不是整体命中率的大幅提升。同音姓名、同长度近音词以及库外实体仍会误改。后续应验证实体与上下文的适配性，并单独衡量库外词保留、身份错改和未确认候选；不能只优化已知目标字面召回或CER。
