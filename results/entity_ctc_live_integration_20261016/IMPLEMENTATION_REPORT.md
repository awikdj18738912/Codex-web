# 实体 CTC 旁路与原音复核组合实施结果

已在实体流式会话增加 `off / shadow / on` 三种模式。`off` 是默认值；`shadow` 只记录声学提案，文本由现有原音复核决定；`on` 允许有证据的 CTC 提案作为局部补丁提前出现。CTC 缺失从不否决现有原音复核。短录音最终复核仍可覆盖同一位置的 CTC 补丁。原始 Qwen 转写始终是位置与版本校验的输入。

模型在 Web 服务启动时共享，词库图缓存最多 8 组；每条录音拥有单独的 CTC 编码器状态、候选搜索状态和有序 CPU worker。Web 发送的 16 kHz mono float32 PCM 同时交给 Qwen 和 CTC；普通 Qwen 音频块不等待 CPU worker 完成。CTC 模型流在结束时排空一次，补丁只在原文片段及邻近锚点仍一致时应用。连续事件历史最多保留 256 个块；运行失败或超时回退到原音复核路径。

容量保护增加后，单个 Web 进程最多接纳 8 条并行 CTC 会话，每条会话最多积压 8 秒待处理音频。超过容量的新会话以及音频队列超限的会话继续使用现有原音复核。真实双会话共享 ONNX 推理和 8 槽容量释放均已单独验证。

实现入口为 `system/entity_ctc_sidecar.py`、`system/entity_streaming_live.py`、`system/entity_audio_repair.py`、`system/web_app.py`、`system/web/index.html`、`scripts/start_web.sh` 和 `requirements-entity-ctc.txt`。现有运行中的 Web 进程未重启。新启动的服务可从健康接口读取 `entity_ctc_mode`；浏览器的“实体声学辅助”可选关闭、仅观察或参与修复。依赖安装和启动示例见 `system/README.md`。

## 实际组合质量

已完成冻结 test **1,829 条音频、2,467 个实体提及**的两臂全量真实 Qwen 运行，逐条核验 ID、split、PCM SHA256 和模式；CTC 参数沿用开发集的 gap=-2、margin=0.1，未根据本次 test 调参。下表为完整 cohort 的词面命中率和字符错误率：

| 方案 | 实体命中 | 命中率 | CER | 日志复核检查数 |
|---|---:|---:|---:|---:|
| Qwen 原始转写（保存基线） | 1,224 / 2,467 | 49.61% | 6.76% | — |
| 旧原音复核（历史结果） | 1,314 / 2,467 | 53.26% | 6.50% | 302 |
| 单独 CTC 旁路（保存基线） | 1,675 / 2,467 | 67.90% | 5.43% | — |
| 当前收尾复核，CTC off | 1,957 / 2,467 | 79.33% | 4.52% | 1,413 |
| 当前 CTC＋原音复核，CTC on | **2,037 / 2,467** | **82.57%** | **4.33%** | **1,440** |

相对当前收尾复核，整段组合流程净增 80 个命中，命中率增加 3.24 个百分点。复核检查数增加 27（约 1.91%）；这些是日志中的检查计数，单次检查可能产生多个流式请求，不能当作模型 API 请求数。CTC 最终保留补丁计数为 83，错误计数器为 0；后者不等于没有误改。此次没有证明复核成本下降。

两臂首轮转写规范化后有 2 条不同，严格配对分析将其排除，保留 **1,827 条**。按 canonical 和 gold 提及次数上限裁剪，新增命中 85 个实体提及、丢失 5 个提及；CER 改善 79 条音频、退化 19 条。按 582 个来源组重采样 1,000 次，命中率差值的 95% 百分位区间为 **+2.36 至 +4.29 个百分点**，CER 差值为 **−0.272 至 −0.117 个百分点**。这只反映样本来源组的抽样不确定性，没有覆盖服务重复运行的波动。

丢失的 5 个实体提及分布在 4 条音频，其 CTC 提案数全部为零；至少不能归因为错误的 CTC 直接替换。日志显示部分复核窗口发送量和收尾路径也有差异。当前是两臂各运行一次的系统对照，没有固定复核响应或调度，所以不能把净增 80 全部解释成纯 CTC 因果收益。实体命中使用规范化 canonical 子串计数，没有边界与上下文判断，也不能视为人工核验的实体 precision。

这些质量表评分的是 Web 精修前的 ASR 实体复核输出；真正的 Web 端到端服务另以独立端口验证接线。不能把 ASR 阶段 CER 直接当成最终精修字幕 CER。完整逐 ID 结果、首轮漂移和分母见 `FULL_TEST_REPORT.md` / `full_test_comparison.json`。

## 先前 230 条交集与控制测试

基于已有当前短录音收尾复核结果的 **230 条共同测试音频**和 **100 条控制音频**，用真实本机 Qwen 服务重新流式处理同一 PCM，并同时运行 CPU CTC 与现有原音复核。230 条的 gold 实体提及总数为 280，Qwen 本次首轮转写与保存基线逐条完全一致。每个文件的 SHA256、ID 与词库路径都经过校验。

| 方案 | 实体命中 | 命中率 | CER |
|---|---:|---:|---:|
| Qwen 原始转写 | 100 / 280 | 35.71% | 8.53% |
| 单独 CTC 旁路 | 145 / 280 | 51.79% | 7.56% |
| 当前短录音收尾复核 | 228 / 280 | 81.43% | 5.81% |
| 实际 CTC＋原音复核 | **235 / 280** | **83.93%** | **5.69%** |

相对当前收尾复核，组合方案净多修复 7 个标注实体，没有丢失已命中的标注实体；7 条音频的 CER 改善，没有 CER 退化的音频。100 条控制音频上，Qwen 原始与组合的 CER 均为 1.07%，没有新增自动词库 canonical 审计候选。这个审计不等于人工确认的 precision。

这 7 次新增命中集中在两个名称（“刘英儿”和“纪源资本”）、4 个来源组。这是先前交集测试，不能代替上面的全量结果；100 条控制仍单独报告，未混入全量 test 分母。

质量跑数加速提交音频，因此不能把它的逐条 elapsed 时间当作交互延迟。230 条测试音频的原音复核检查数在当前方案与组合方案中都是 **175 次**；组合并未降低这一批样本的检查量。CTC 增加了 CPU 计算，默认保持关闭。

## 真实语速配对延迟

从上述 230 条中仅按输入 ID 固定 hash 选取 8 条，每条交替运行当前原音复核 `off` 与组合 `on`，共 16 个会话、666 个音频包。每个包在对应音频可用后提交；相同样本的两次运行，PCM 与 Qwen 首轮转写均一致。模型和词库在计时前准备。

| 方案 | 首次出字中位数 | 最后一包音频提交后至最终文本，中位数 / 最大值 | 原音复核检查 |
|---|---:|---:|---:|
| 当前原音复核 | 2.240 秒 | 412 / 661 毫秒 | 8 次 |
| CTC＋原音复核 | 2.238 秒 | 459 / 704 毫秒 | 7 次 |

按相同录音逐条计算，组合的尾延迟差值中位数为 **+23 毫秒**。在一条录音中，CTC 使两次原音复核候选跳过，日志检查少一次；其余录音没有减少检查。8 条音频的中位数与最大值都不能视为服务 p95 或并发负载保证。8 条的事后质量诊断是原音复核 9/11、组合 11/11，样本过少，不作为整体质量结论。

这 8 条音频的 CTC CPU 计算时间合计约为源音频时长的 0.20 倍，设置为每路两线程。它与 Qwen 主服务并行，仍然占用额外的 CPU 容量；当前测试没有证明多并发会话下的资源收益。

## 适用范围与下一步

这批实体词库的领域划分曾有参考文本辅助，属于已知场景条件；全量 82.57% 也不能推断到未知领域或自动领域路由。先前 230 条交集的 83.93% 作为历史结果保留，不作为全量结论。CTC 分差沿用先前 171 条开发集选出的参数；它不是正确概率。本实现复用了实验目录中经过对照验证的 CTC 前端和候选搜索代码，今后从仓库独立部署时需将其连同模型打包。

另一个部署差异是词库：8081 服务当前使用的数据库只有 13 条启用实体，本次挑战集使用的是独立的 37 个已知场景词库。没有把测试集词库自动并入在线数据库；因此上述质量数字不代表直接在当前 8081 词库上运行的收益。独立 8088 服务曾用真实 Refiner、Qwen、CTC 和在线数据库完成端到端 Web 冒烟测试，健康接口及会话状态正常；该测试音频不含在线数据库中的实体，只验证接线和故障回退，结果在 `real_web_8088_smoke.json`。测试服务随后已关闭。

另用场景词库的独立副本启动真实 Refiner Web 服务：对“王正章→王正璋”音频，最终字幕包含正确姓名；对“刘英→刘英儿”音频，CTC 产生并提交 1 个局部补丁，最终字幕也包含正确姓名。这两次只验证真实 Web 的发布链路，记录见 `real_web_8088_scenario_fix.json` 和 `real_web_8088_ctc_patch.json`。Refiner 已加载，但这些音频被门控跳过，实际精修模型调用为零，不能称为精修效果验证；测试服务已关闭，原 8081 服务未重启。

本次全量系统对照观察到整体质量提升，同时有局部 CER 退化，**没有降低复核检查数**。默认保持 off，可使用 shadow 收集独立场景证据。后续需要固定复核响应或重复配对来隔离 CTC 增量，再在另行冻结的长短混合、未知领域和含错误词库候选的数据上，按质量、误改、尾延迟和调用成本联合决定是否默认启用。不得根据本次 test 个案继续调阈值后仍将其称为未见测试集。

方法依据是 [CTC-WS（Interspeech 2024）](https://arxiv.org/abs/2406.07096) 及 [NeMo 维护者实现](https://github.com/NVIDIA-NeMo/Speech/blob/main/nemo/collections/asr/parts/context_biasing/ctc_based_word_spotter.py)，本项目的独立 Qwen 旁路并非该实现的完整复现，也不能把 CTC 词检索本身作为新的论文贡献。

最终相关回归测试 **144 项通过**，9 条依赖弃用告警；记录见 `final_regression.log`。冻结数据、词库、模型及推理来源 52 项哈希校验全部通过；Shell 语法、Python 编译与 `git diff --check` 通过。8081/8051/8766 健康接口正常，独立 8088 测试服务已关闭。验证详情与当前源码哈希见 `implementation_verification.json`。
