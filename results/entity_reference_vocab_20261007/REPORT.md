# 按参考转写预建医学实体库：命中规则与实际测试

2026-10-07。本轮按用户指定的方法执行：**从有音频及配套参考转写的医学数据中抽取标准实体，汇总为一份领域库，再转录并比较实体纠错效果。没有把 ASR 的错误写法添加为永久别名。**

结果：用户提出的“截肢手术／介质手书”命中问题已在文字功能检查中修复；新真人录音中额外规范了一个标准医学名的两个音频版本。整体收益仍小，不宣称已解决广泛医学近音错误。

## 1. 数据与预建库

音频为作者公开的 [MultiMed](https://huggingface.co/datasets/leduckhai/MultiMed) 中文 train 真人医疗录音。医学词表辅助抽取来源为 [CBLUE/CMeEE](https://github.com/CBLUEbenchmark/CBLUE) 标注词，实体本身必须实际出现在所选录音的参考转写中。

选择 64 条未参与前两批 train 音频解码的片段，每条原音和固定种子的 5 dB 白噪声版本，共 **128 次真实 ASR 解码**。在识别之前进行参考文本语言／时长筛选和实体边界审核：把设备、术式的完整名称保留下来，避免仅取“胰十二指肠切除术”内部的“十二指肠”等片段。

最终库有 **45 个标准名称、81 次参考出现**，包括疾病、症候、检查、药物、器官、设备和术式，如二氧化碳潴留、甲状旁腺激素、干燥综合征、动静脉瘘手术、胰十二指肠切除术、混合静脉血氧饱和度监视仪。各名称附对应参考句及位置，便于审阅。

这是**从待测参考中提取词表的已知词表覆盖实验**，符合用户要先排除“正确实体没入库”的测试目的；不是未知词表泛化验收。标准名、词库与选样在第一次 ASR 解码前冻结，原文件哈希结束时仍一致。优化阶段沿用相同 45 个名称，增加同域其它名称作为独立语境词，未传入逐条正确句子。

### 参考质量限制

MultiMed 提供配套参考，但部分字幕不是逐字听写，有英语缺标、片段截断和术语表述差异。仅按字幕语言／字数筛选不能保证原音没有这些情况。本轮没有伪称全部参考已经过人工逐字核验，也没有用整体 CER 宣传准确率。

例如 `train_0845` 的参考写“腹腔镜手术”，原音及噪声 ASR 均写“内窥镜手术”；这组需要核对参考与原音，不能仅凭库中有腹腔镜就强行改名。`train_0274` 出现另一不同部位的术式名称，也保持原文。这些例子没有记作纠错成功。

后续严格验收应先核准目标实体的参考名称与原音；有疑问的片段单列，不能据此制造正例。本次结果作为开发与回归证据。

## 2. 用户示例揭示的规则问题

单独登记“截肢手术”，原输入“患者需要接受介质手书”在旧规则中没有候选：

| 项目 | 原值 |
|---|---:|
| 声母韵母完整匹配分 | 1.0 |
| 字形匹配分 | 0.25 |
| 综合分 | **0.7925** |
| 候选门槛 | **0.8** |

即使有正确标准名，候选仍在进一步验证之前被混合评分过滤。这里比较的是声母韵母，**不表示源字声调相同，也不表示已经对原音做了声调校验**。

本轮将可验证的完整字音证据放到混合分过滤之前：对所选 `medical` 领域、`TERM`、normalize、auto 的中文术式，要求标准名唯一、独立词边界成立、角色／位置合适，才执行规范。单独术名短句或明确“接受／进行／安排／完成／做”等术式位置可以使用已登记标准名，不必手工录入错误别名或语境档案。

| 文字功能检查 | 新结果 |
|---|---|
| 介质手书 | **截肢手术** |
| 患者需要接受介质手书 | **患者需要接受截肢手术** |
| 医生拿到了介质手书 | 保留原文 |
| 患者需要接受截指手书 | 保留原文，不能猜改不同身体部位 |
| 同时登记截肢手术与截指手术 | 同音歧义，保留原文 |

上述“截肢”是用户提供的**构造文字检查**。本地 MultiMed 中文材料中未找到截肢术名，本轮没有冒充测试过真实截肢录音。其单独配置见 `user_example_entities.json`，未混入医学音频的 45 项计分词表。

## 3. 真人音频对照

相同原始 ASR 输出，分别比较标准库、语境配置、完整同音改进与严格单字近音规范。ASR 没有接收参考句或词表提示。

| 配置 | 名称保留／参考出现 | 相对初始配置的改善版本 | 退化版本 |
|---|---:|---:|---:|
| 原规则，只有参考提取的标准名 | 110/162 | 0 | 0 |
| 原规则，附固定医疗语境 | 110/162 | 0 | 0 |
| 完整同音命中改进，近音开关关闭 | 110/162 | 0 | 0 |
| 优化库的同域实体语境，近音开关关闭 | 110/162 | 0 | 0 |
| 相同优化库，符合条件的长医学词显式开启单字近音规范 | **112/162** | **2** | **0** |

最后两行名称及语境完全一致，唯一差异为近音权限。

两个新增成功版本均来自 `MultiMed_Chinese_train_0961` 的同一条真人录音：

> 原音／噪声 ASR：……仍然持续高烧，**二氧化碳储留**，潮气量很高。
>
> 参考及新输出：……仍然持续高烧，**二氧化碳潴留**，潮气量很高。

只替换“储→潴”，其它内容不变。语境由同一预建名单里已正确出现的“呼吸机”“潮气量”提供，没有根据错误添加“储留”的别名。

这里是**一个独立录音的两个版本**，不能称为两条独立成功录音。名称出现计数也是词表内最长非重叠出现计数，不是完整人工 NER 准确率。尚未恢复的名称包含漏词、跨脚本缩写、多个音节错误、另一合法名称及参考需复核情况，不能全部归因于单个替换门槛。

## 4. 近音规则的范围

新增 `allow_near_spelling` 为词条独立开关，默认关闭。只有明确开启的 5–16 字长医学术式／症候名称满足下列条件时，才把候选升为可执行修改：

- 源文与标准名仅一个字不同，其余字及音节一致；该音节只允许一个拼音字母编辑。
- 不修改身体部位、方位、否定、数量、化学元素等敏感字符。
- 不切入原文独立已知多字词、不改已知完整词或已保护实体；标识符、标点与拼写讨论位置保留。
- 候选唯一，语境绑定正确，达到配置的独立语境要求。
- 名称限定在特定医学术式／症候词尾；此规则不用于任意药名替换。

“甲状旁腺激素→甲状腺激素”等两个有效名称之间的变化、“经鼻→经皮”、“二氧化氮→二氧化碳”及另一药名不会按本规则自动改写。明确人物称谓位置也不能用医学词库把医生“高雪雅”改成“高血压”。

成功修改记录为 `CONTEXT_NEAR_PINYIN`，后续精修失败时保留规则已验证的局部规范。没有修改原 ASR、通用精修模型、Web 或数字规则。

## 5. 回归与完整模型链路

| 验证 | 结果 |
|---|---|
| 新近音规则与相同词库关闭权限相比：1,000 条正确医学文本 | 0 新增变化 |
| 相对于上一轮已保留版本：2,121 条历史回归输入 | 0 新增变化；此前收益保留 |
| 新音频及正确文本的隔离开发探针：1,128 条 | 2 个版本改善、0 个版本退化 |
| 6 份固定真实 ASR 响应，真实 GPU Refiner 的 12 次 Web 回放 | 两个版本复现“储→潴”；其余四份输出相同 |
| 全量项目测试 | **412 passed** |

完整回放中两组库的名称、语境、ASR 输入、数字与精修参数相同，只切换近音权限。选样包含新增成功录音和另两个有效／存疑名称的控制例。这部分是开发质量复现，不是独立生产验收或实时延迟基准。

## 6. 产物与使用

- `selection.json`：64 条音频路径、参考、抽取实体及来源。
- `reference_entities.json`：45 项标准名及参考句证据。
- `reference_terms.db`：识别前冻结的初始实体库。
- `optimized_terms.db` / `medical_entities.json`：相同标准名，包含同域语境和显式近音权限的优化配置。
- `user_example_entities.json`：单独的截肢文字示例，标准名没有错误别名。
- `asr.jsonl`：128 次真实音频解码、PCM 哈希、分块和最终响应。
- `baseline_summary.json` / `final_summary.json` / `final_changes.json`：对照结果。
- `core_near_controls.json` / `historical_regression.json` / `web_summary.json`：安全及完整链路复现。
- `full_tests.log` / `scope_verification.json`：测试及范围证明。

可以导入到独立测试库再开始新的医疗会话：

```bash
PYTHONPATH=. python -m system.entity_context_cli \
  --db /绝对路径/测试实体库.db import \
  --input /绝对路径/medical_entities.json
```

转录时选择医疗领域，使用 normalize 策略和 auto 模式。近音权限和语境可随配置一起导入，不需要维护每个 ASR 错字别名。正式用户库没有自动导入这批数据，运行中的服务也未重启；使用新规则需要进程加载更新后的实体模块。

实体模块的新命中／规范能力及测试配置已保留，旧词库不自动开启近音权限。由于本轮仅新增一个独立录音的成功案例，仍需更多经核准参考的录音验证覆盖范围。
