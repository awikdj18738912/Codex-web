# 错误对照表与审核、修复、重生成闭环

旧审核中已有“教师放行但人工/独立复核发现错误”的案例。本轮把错误分类、证据、修复和失败处理变成可追溯记录，覆盖完整 99,852 条，而不只检查未处理尾部。

- `error_catalog.json`：稳定错误编号、判定标准、例外及来源。政策示例明确标注为示例，不冒充观测样本。
- `错误对照表.md`：可读类别表和最近 100 条错误实例，运行时每 25 条刷新。
- `/home/aim0/data/ASR/dataset_error_loop_20261024/错误实例对照表.tsv`：完整错误原文、错误输出、修复输出、重生成输入输出及最终状态，可用表格软件打开。
- 数据目录 `events.jsonl`：逐次教师响应、请求及提示词哈希、错误表版本、调用端点。
- `error_occurrences.jsonl`：每次命中，包含原文、错误目标和可核对的逐字证据。
- `results.jsonl`：每条输入的初审、修复后复审、重生成后复审和完整文本。
- `progress.json`：完成量、状态分布和错误表版本。以上是过程统计，不是独立质量通过率。

## 处理规则

1. 优先已知问题，对全部旧训练对按错误表回查；已成功修复的旧目标作为候选输入。
2. 对明确目标错误修复一次，再按完整错误表审核。仍命中明确错误时，不重复补丁，重新生成完整口语/精修训练对。
3. 原文已确认无效则直接生成新对；原文语义不确定则保留待复核，不冒充已确认错误。
4. 重生成只接收原场景、弱类别线索和新种子编号，不把旧错误文本喂给生成器。新对仍保留原 train/val 归属；导出检查输入与输出重复和跨集冲突。
5. 最多生成两次。再次失败、语义不确定或接口/格式异常均进入待复核，不强行通过、不无限循环。
6. 新错误先尽量归入已有类型。确需新类别时保留原文证据，第二次教师调用确认后加入错误表；不确定只记录，不自动提升为有效规则。同一教师二次确认不是人工金标。
7. 不是关键词或正则删词：撤回值可以删除；有效英文、命令、否定、条件、语气须按上下文保留。数字规则仍在模型外，不给模型增加数字格式化任务。
8. 每条候选除错误表审核外，必须通过专门的忠实度与清理度审核。已确认的有效命令/英文方法名另按证据清单核对，教师泛化的通过结论不能覆盖已确认遗漏。
9. 错误表增加类别后，早期放行候选补审新版本。最多进行三轮版本追补；仍落后最新版本的候选转待复核，不能导出。记录所有修订，按样本ID取最终状态，不覆盖历史。

GPU 路由复用旧任务 `gpu_routing.json`，用户关闭 GPU1 时只调用 GPU0；每个端点并发 16，CUDA Graph 服务不重启。旧记录保留，原训练文件不覆盖。旧客户端在批次边界停止，避免两套全量审核争抢 GPU0。

## 2026-10-24 持续补位调度

用 64 个有界样本 worker 持续补位，模型请求按每张卡的当前在途数分配，每卡仍最多 16 个请求。
删除每 32 条等待整批结束的屏障；同一样本的后续阶段可以使用另一张空闲卡，tokenize 和 completion 始终在同一卡完成。
错误表、三项审核、证据验证、温度、输出预算、修复/重生成上限不变；补审也使用相同的持续调度。
迁移时旧代码、manifest、完成记录快照与变更记录保存在数据目录 `scheduling_versions/`；客户端重启，教师服务不重启。

```bash
python results/refiner_dataset_repair_20261024_error_loop/run_error_loop.py --concurrency-per-gpu 16 --record-workers 64
```

完整闭环结束后用 `export_candidates.py` 导出候选版本。候选仍需独立分层抽查及学生模型小规模对照，不承诺零错误。
