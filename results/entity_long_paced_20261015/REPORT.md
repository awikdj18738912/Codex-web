# 连续长音频：纯转录与实体修复的真实语速对照

输入为现有水利科普原音的 90–210 秒连续片段，共 120 秒，无拼接、无插入静音。
冻结 40 条水利场景词库；两臂各两轮，顺序为 raw→entity、entity→raw。
raw 直接请求真实 Qwen 服务；entity 使用同一服务及当前默认参数的 CTC＋原音复核。
每 160 毫秒提交对应新音频；模型和词库准备在计时外。没有运行下游 Web 精修。

## 本次结论

两轮配对的总耗时差中位数为 +42.2 毫秒，最后一包到最终返回的等待差中位数为 +60.5 毫秒。这段音频上的平均流式开销较小；单次第一轮总耗时略快不代表实体模式能加速 Qwen。

实体组的单次最大瞬时发送落后达到 0.746 秒，随后追上音频时钟；不能只用收尾时间评价全过程的抖动。

两次实体模式均运行了 376 个 CTC 块事件、各进行了 2 次局部原音复核检查，但最终修改数为零，不能据此证明长音频中的实体修复有效。全部四次运行都在约 88.5 秒短暂输出“构皮滩”，约 90.4 秒又变为“构壁滩”，最终未恢复。该现象是初稿的拼写变化，非实体模块提交补丁后被覆盖。

第一轮两臂首轮转写还存在“净流量/径流量”及标点差异，第二轮逐字一致；本次是速度诊断，不把这些变化当作实体模块的质量收益。

## 适用范围

- One natural continuous excerpt, two counterbalanced repetitions per arm; not service p95.
- No human reference, no CER or entity precision/recall claim.
- 40-term known-scene water glossary prepared using historical content; not unknown-domain evaluation.
- Timing excludes model/library preparation and downstream Web refinement.
- Returned text/patch observation times are not audio entity-end timestamps.
- Real-time pacing measures user-visible streaming latency, not offline file throughput.

共核验 3000 包，PCM 和词库 SHA256 匹配。逐包、逐词时序见 `timing_audit.json` 及 `run/events.jsonl`。

地名拼写参考：[三峡集团项目介绍](https://www.ctg.com.cn/sxjt/bhtkgzt/bwx.html)、[国家发改委“构皮滩”项目资料](https://www.ndrc.gov.cn/fggz/zcssfz/dffz/202108/t20210831_1295632.html)。
方法背景：[CTC-WS](https://arxiv.org/abs/2406.07096) / [NeMo 实现](https://github.com/NVIDIA-NeMo/Speech/blob/main/nemo/collections/asr/parts/context_biasing/ctc_based_word_spotter.py)。
