# 数字后端速度对比（2026-10-14）

36 条文本窗口：12 条纯数字、12 条数字与口语清理混合句、12 条非数字对照。每条每种方式运行 3 次，共 432 条观测。

同一 RTX 3090、同一个本地 AgenticASR-Refiner 实例；预热后同步 CUDA，交错多轮计时。以下是文本处理耗时，不含模型加载、ASR、音频上传、WebSocket 调度或线上排队。

两条 Web 链路使用相同原生 tri_state 门控；学习门控和实体数据库关闭。每条样本视为一个已完成窗口，single_window=True，未执行累计流式 K=3 调度。

直接纯 Refiner 使用原始输入，单次模型生成后仅移除元数据；没有数字校验或兜底。关闭 zh-itn 的 Web 链路包含已有 Python 数字兜底和完整性校验。zh-itn 链路先处理数字、按门控调用语言精修、再校验数字。

## 结果解释

- 纯数字句：相对直接纯模型，耗时变化 -91.3%；相对关闭 zh-itn 的 Web 链路，耗时变化 -94.7%。
- 数字 + 口语清理：相对直接纯模型，耗时变化 +14.9%；相对关闭 zh-itn 的 Web 链路，耗时变化 -40.5%。
- 本次等比例样本合计：相对直接纯模型，耗时变化 -43.6%；相对关闭 zh-itn 的 Web 链路，耗时变化 -59.8%。

纯数字组仅执行规则时平均 6.17 ms；开启规则的完整 Web 链路平均 39.54 ms，中位数 7.56 ms。36 次输入中仍有 3 次模型调用，均来自电话数字串被门控识别成重复信号。

混合组 zh-itn 链路共调用模型 45 次（含 9 次重试），关闭规则的 Web 链路调用 69 次（含 30 次重试）；直接纯模型固定调用 36 次且不检查结果。规则并没有让模型必然推理更快，主要节省数字专用调用，并在部分样本中减少数字错误导致的重试。

非数字对照：两条 Web 链路调用数相同，耗时相差约 1.2%；相对直接每句都调用模型的收益主要来自两条链路共同使用的门控，不能归因于 zh-itn。

## 输出核对和限制

逐句输出见 OUTPUTS.md，原始观测和模型轨迹见 observations.jsonl。本次没有独立人工准确率评分。

- 本次直接纯模型将 123万7851元 写成 137,851元；将 95142辆 写成 91542辆；将版本 4.0.8.23.1 写成 v4.0.8.3.1；电话数字串也有丢失/改序。规则链路保留了这些数值。
- zh-itn 仍保留孤立的“大概有三十七度”，与直接模型的 37度 写法不同。混合链路有候选被拒绝后保留原有口头语的例子；速度不能代替质量验收。
- GPU 上有其他现有服务；采用同模型、交错顺序、三轮重复减轻顺序影响，但结果不能代表全部线上负载。
- 等比例测试集里的总耗时改善，不能直接外推成每次实际转录的加速比例。
