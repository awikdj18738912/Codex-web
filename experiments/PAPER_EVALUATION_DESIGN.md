# 当前精修模块的论文评估设计

日期：2026-10-10。范围：当前仓库的 ASR 后精修链路；默认以中文和常见中英混合为研究范围。以下实验、数量与验收目标是建议，不是已经完成的结果。

## 1. 建议的论文问题

建议围绕“在保持最终表达意图和关键信息的条件下，如何减少不必要的神经精修与错误编辑”组织论文。方法可以包含局部编辑、独立验证和选择性调用，但应明确哪一部分是本次新增贡献、哪一部分继承 AgenticASR。

现有 AgenticASR 已研究 ASR–Refiner、滑动窗口、最终意图整理及 AASR-Bench。因此，单纯新增规则、使用 K=3 或串联 ASR 和 Refiner，不能直接作为新方法的充分论据。已有研究也使用不确定性选择纠错，以及预检测—纠错—验证流程；本项目可进一步研究实际操作收益监督、缺少可信置信度时的路由，以及同等成本下的误改控制。

参考：

- [AgenticASR 原论文](https://arxiv.org/html/2607.28175v1)。
- [Multi-stage Large Language Model Correction for Speech Recognition](https://arxiv.org/abs/2310.11532)。
- [Fewer Hallucinations, More Verification](https://arxiv.org/abs/2505.24347)。
- [Learn then Test](https://arxiv.org/abs/2110.01052)，仅用于有独立校准数据时的风险控制设计。

如果学习型门控没有实现，论文应聚焦当前局部编辑和保护机制；如果论文以收益学习门控为贡献，必须补齐训练、独立风险校准和完整会话实验。

现有结果的使用边界：

1. `results/gate_pilot_20261009/REPORT.md`：500 个决策样本中，343 个 always 与 rules 输出逐字相同。只能证明这些局部操作没有净输出变化。人工已标注数为 0，不能据此报告有益纠错率。
2. `results/gate_pilot_20261009/ASSISTANT_REVIEW_REPORT.md`：157 个变化样本有辅助文本判断，但全部未核对原音，不能当成人工真值。
3. `results/refiner_local_edit_20261009/protocol_audit/REPORT.md`：503 个旧提示响应全部被严格解析拒绝，反映格式不兼容；不是新提示或新模型的质量实验。
4. `results/entity_methods_comparison_20261009/REPORT.md`：225 条 MultiMed 音频中，辅助识别有实体增益也有丢失，并出现提示复制。该词库来自被测参考，属于已知词表覆盖实验。
5. `results/entity_echo_guard_20261010/REPORT.md`：原音复核处理了已发现的提示污染；这些样本已经用于修复开发，应保留为回归材料。
6. `results/oncology_podcast_20261008/` 与 `results/entity_repair_20261009/`：播客无人工标准转录，标准名称出现次数不能解释为实体准确率；独立 60 秒会话也不能替代整段连续会话实验。
7. `results/learned_gate_latency_20261009/REPORT.md`：测的是编码器与未训练分类头的 CPU 开销，不是学习门控准确率或系统加速结果。

## 3. 四个研究问题

- **RQ1，收益：** 相比原始 ASR、规则基线和原版 Refiner，模块能否改善最终意图文本，同时保持内容正确？
- **RQ2，风险：** 局部编辑与验证能否降低新增的实体、数字、否定、条件关系错误，并保留有效修复能力？
- **RQ3，成本：** 在相近质量或相同调用预算下，选择性精修能否降低包含门控、重试和复核在内的总成本？
- **RQ4，流式与泛化：** 在完整会话、晚到自我修正、未见说话人/来源/别名和另一 ASR 后端上，收益是否仍成立？

## 4. 数据与标注

### 4.1 三类互补数据

| 数据 | 作用 | 使用条件 |
|---|---|---|
| AASR-Bench | 与原方法对齐，报告 Content/Format/Filter/Rephrase 与 pass-through 控制 | 使用官方划分与 rubric；固定 Judge，不能拿测试集调提示或阈值 |
| 新的自然录音 | 主结论：真人精修质量、误改与流式表现 | 新来源，保留原音与时间戳，人工双参考；既有修复材料不混入最终测试 |
| 独立挑战集 | 检查稀有失败：同音实体、数字范围、否定、正常强调、条件句、晚到改口 | 与自然分布结果分开；不将平衡挑战集的风险当作线上自然风险 |

建议第一轮收集 60–100 个独立来源、约 800–1200 个短片段，并保留至少 20–30 段连续长会话做工程压力测试。数量是起点，实际需要多少取决于来源多样性、误改事件数和置信区间。几十段长会话不足以证明 1% 的低风险保证。

学习门控若需要扩大训练，可使用 TTS→真实 ASR 的辅助数据；TTS 原稿不自动等于实际发声，漏读关键词、数字或重复会污染标签。相同原稿的噪声版本、声音变体与同模板文本要留在同一划分。合成数据和真实数据分别报告。

### 4.2 双参考及编辑依据

每条真实样本至少标注：

- `verbatim_reference`：实际说出的词，包括口吃、自我修正和有意义重复。
- `intended_reference`：保留最终表达意图的整理文本，不补事实、不摘要；保留有意义强调。
- 实体与数值跨度、否定和条件关系、应删除的口语跨度、可接受编辑及音频时间范围。
- 来源/节目/说话人分组、领域、语言、参考可核验状态。

例如“明天交，不对，后天交”：verbatim 保留完整改口，intended 是“后天交”。例如“这些泵站一级一级地向高处提水”：intended 保留“一级一级”。不能把所有重复都标为口吃。

至少两位标注者独立审核变化样本及风险样本，隐藏系统名称、随机排列输出，分歧由第三人或协商裁决。报告标注一致性、听音比例与 uncertain 数量。医学材料核对说话人说了什么，不把整理任务变成医学观点校正。

建议收益标签为 benefit/neutral/harm/uncertain：同一操作既改善格式又新增关键信息错误时记 harm；另分轻微格式退化与事实/关键语义退化。验证器接受、文字发生变化或 CER 下降均不能单独作为 benefit 标签。

### 4.3 划分与泄漏

按录音、节目或可关联说话人建组后再划分。学习方法建议 train/dev/calibration/test 四部分，比例可从 60/15/10/15 起步，再按独立组数调整。规则方法至少有 dev/test。

特别注意：`pipeline/scripts/export_sft.py::stratified_split` 当前按场景和目标长度分层后随机分行，不是按原始录音/模板防泄漏划分。论文数据必须另外生成固定来源组清单，不能直接把该导出器的随机验证集当作独立泛化证据。

实体词库在测试前冻结：标准名可来自预先公开的领域词表或用户提前提供的资料；测试错误别名、逐句参考和从测试答案提取的选择列表不可用来调库。可另报“参考提供完整词表”的 oracle/已知词表条件，但要明确区别于独立泛化。

## 5. 主对照系统

| 编号 | 系统 | 回答的问题 |
|---|---|---|
| B0 | 原始 ASR | 初始识别与内容基线 |
| B1 | ASR＋共有确定性处理，不调用神经精修/局部复核 | 规则本身的收益，也是选择调用的基线 |
| B2 | 原版 AgenticASR Refiner | 相对原方法的增量；尽量复现其公开设置 |
| B3 | 固定本项目窗口、规则与验证链，所有就绪任务都执行 | 同一执行链下 always 的收益与代价 |
| B4 | 同一执行链下当前规则门控 | 现有规则路由对照 |
| B5 | 与 B4/B6 匹配调用或实测成本预算的随机选择 | 验证收益是否超过简单减少调用 |
| B6 | 完整候选方法 | 新局部编辑模型/学习门控，按实际完成情况纳入 |
| O | 根据人工成对标签选择的局部 oracle | 仅表示离线局部可选择空间，不是可部署或全会话上界 |

质量实验先冻结 ASR 全部事件与 source revision。除被研究因素外，模型、数字规则、词库、窗口、输入上下文、缓存、重试、最终策略都一致。原版完整复现 B2 与同链路增量对照 B3/B4 应分开解释。

**代码中的关键混杂：** `system/web_app.py` 根据 `mode is TRI_STATE` 切换标点窗口组织。因此直接比较启动参数 off 与 tri_state，同时改变了调用策略和输入分段。门控主实验须固定 tri_state 的窗口路径，并单独注入 always/keep/current/learned 决策；另外做整体配置的端到端对照。

不能把 final-only 当作“同一信息量下”的纯门控对照。它看到未来完整文本、等待更久，应放入流式质量—等待对比。

## 6. 指标与分母

### 6.1 质量

主指标为 AASR 四维得分与人工信息保留/新增错误，而不只看 CER。

- 原始 ASR 对 verbatim：CER（中文）、WER（英文）、MER（中英混合）。
- 最终精修对 intended：同样的表面一致度，辅以 rubric 与人工判断；若仍对 verbatim 计算，要明确它会惩罚合法口语删除。
- 数字等价格式使用事先冻结、对两侧一致的归一化，另外报告数值、单位、范围、顺序是否保持。
- 标点/格式单独评分，不能在去除标点的 CER 中评价断句收益或条件句破坏。
- 长录音给出微平均整体错误率及录音级分布，避免少数长输出把结果完全主导。

`experiments/scripts/text_metrics.py` 的 WER 对中文连续字串按正则取单位，不能作为标准中文分词 WER 宣传；主用中文 CER、英文 WER、混合 MER。当前普通归一化不等于完整数字等价判断，医疗脚本与通用脚本也需统一评分契约。

Judge 固定模型版本、提示、采样与重复判定方法；对人工样本验证一致性并保留逐项回答。失败、超时和不可解析项须报告覆盖率并预先指定计分，不能只对成功项展示漂亮均分。

### 6.2 安全和有效编辑

分别报告以下量，避免混用分母：

- **实质退化率** = 相对共有规则基线出现新增实质错误的完整会话数 / 全部被评会话数。
- **正确内容误改率** = 原本正确且被改坏的标注单位数 / 原本正确的标注单位数。单位可为句子或关键跨度，但全表统一。
- **净收益分布**：相对同一个基线的改善、无实质变化、退化会话数；两者同时发生另报事件数，不用净数掩盖错误。
- **有效编辑精确率** = 人工确认有益且无新增关键错误的实质编辑数 / 全部实质编辑数。
- **有效修复召回率** = 成功完成的预标注应修复操作数 / 全部预标注应修复操作数。多种合理写法按编辑目标判定，不强求唯一字符串。
- 数字/单位/范围错误、实体错误、否定翻转、指代与条件关系破坏、新增事实/信息遗漏分项报告。

实体纠错另记：需要修复的提及中有多少正确修复；不应改变的提及中有多少被误改；全部实体修改中有多少改对。改成另一个错误名同时算一次失败修复和一次错误修改，但不要把它混入“原本正确实体”的误改分母。按已知标准名/未见错误别名/未见标准名、同音歧义、有库/无库分组。

标准名在输出里出现，只是保留指标。若没有对齐原音、目标提及和新增提及，不能称为实体精确率；新增词表名称与提示复制要单独计数。

### 6.3 验证器

保存校验前候选和校验后输出，用人工标签测：

- 危险候选拦截率 = 拦住的有害候选 / 全部有害候选。
- 有益候选误拒率 = 拒掉的有益候选 / 全部有益候选。
- 重试成功率、回退率，以及最终有效修复/实质退化率。

协议拒绝率不是质量指标。一个永远回退的系统可能零新增错误，却没有修复收益。

### 6.4 门控与成本

若训练学习门控：报告 benefit/harm 的 AUPRC（附类别基率），收益召回、被执行操作的 harm 比例及概率校准；分类 accuracy/F1 只作诊断。主结论仍来自最终会话效果与成本。

成本账本应包括普通精修、严格重试、局部重复/删除复核、plausibility 前向、实体音频复核、门控 CPU/GPU、token、缓存命中/失效、模型加载与资源峰值。加载成本与稳态分开。

同时报告：模型调用/音频分钟、调用/千字、实际神经前向数、输入输出 token、累计计算时间、CPU 开销、峰值内存/显存、端到端墙钟。调用次数下降不自动代表墙钟加速。

## 7. 最必要的消融

### 7.1 局部编辑模型与协议：2×2

| 权重 | compat | strict_local |
|---|---|---|
| 原始 checkpoint | 当前可用基线 | 用严格新提示重新生成，不复用旧整段响应冒充新推理 |
| 格式/纠错适配后的 checkpoint | 分离微调收益 | 完整局部编辑方法 |

报告 JSON 合法率、可执行补丁率、正确内容 keep 率、有效修复召回、语义误改和真实成本。strict_local 每次只允许一个修改，整段方法可改多处；同时报告多错误样本上的遗漏，并在相同最大调用/编辑预算下比较。若允许迭代补丁，次数与成本必须计入。

格式合法只能验证接口。现有合成格式 test 可用于格式能力，不能替代真实 ASR 独立测试。

### 7.2 保护与验证

以完整方法为中心，分别去掉实体保护、数值语义校验、内容校验；最后比较无验证、验证无重试、验证有重试。其他条件一致，仅离线执行风险消融。衡量拦截和有效修改损失，不必穷举全部组合。

### 7.3 门控

固定窗口与执行链，比较 always、当前规则、随机同预算、学习型；学习型再做仅文本、加状态/实体数字摘要、加正则信号的消融。当前 Qwen 分数为未校准且可能只覆盖生成后缀，只有核对分数覆盖并在独立开发/校准数据上处理后，才纳入可靠置信度基线。缺少真实 N-best 时不能声称复现依赖 N-best 的论文方法。

扫描开发集上的小组阈值，画质量—实测成本与实质退化—调用比例曲线。测试集使用已冻结的候选政策；不事后选最佳测试阈值。

### 7.4 实体：2×2

复用四组设计：关闭 ASR 提示/关闭实体后处理、仅后处理、仅 ASR 提示、二者都开。增加提示污染与原音复核开销。主实验词库从测试外预建；词库大小、干扰项比例、同音竞争和领域错配作压力测试。

## 8. 完整流式评估

分三个层级，不能互相替代：

1. **冻结最终快照：** 评价局部操作及门控可选择性，适合廉价排查。
2. **按事件时间的完整会话回放：** 逐条重放 ASR 假设、修订、VAD 片段、finish；每种策略独立缓存/会话记忆，比较最终文本、中间文字与全成本。输入只能使用当时已到达的信息，DEFER 在最终阶段必须结束。
3. **真实音频与调度：** 同硬件、同 PCM、同语言、VAD/解码设置；既测实时节奏输入，也测文件加速上传，分开报告。保留排队、丢弃旧任务与最终收尾记录。

流式对照至少包括 final-only、固定窗口 always、固定窗口规则/学习门控。K=1/3/5 和缓存开/关是另外的窗口/工程实验，不与门控主比较混在一起。

建议定义：

- 首个原始文本时间与首个 clean 文本时间，不能把任何 update 事件直接算作有质量保证的 clean 输出。
- 从对应语音结束到可见 clean 文本的 p50/p95 滞后；对晚到改口，另算修正证据到达至输出正确更新的时间。
- **稳定显示延迟**：相应内容第一次显示且之后不再变化的时刻与语音时间之差，离线根据全轨迹计算。
- **回改负担**：连续可见输出去除纯尾部追加后的删除/替换字符数，除以最终文字长度；须区分 ASR 自身修订与精修新增回改。
- 结束后等待时间、积压/过时任务数、过时结果覆盖新版本次数、缓存复用、长会话内存增长。
- 加速文件处理 RTF = 处理墙钟 / 音频时长；实时输入的墙钟含播放时间，应另外报告处理滞后和 finish 等待。

例如先说“周五交”，之后说“不对，周六交”，不能要求更早快照提前输出“周六”。标注改口证据的到达时间，检验 DEFER/活动窗口是否最终保留正确意图。

预热后每个速度条件重复至少 5 次，交替/随机运行顺序，控制并发负载，固定服务和代码。GPU 计时需同步；分开报告独立模块累计耗时和用户可见墙钟。当前 `scripts/benchmark_speed_quality.py` 支持文件连续发送及等待 ack，不按音频播放节奏 sleep，所以它测的是加速文件模式，不能直接叫实时用户延迟。

## 9. 统计、图表与论文结论

所有系统对相同测试来源作配对比较。CER 等差值使用按独立录音/来源聚类的配对 bootstrap，重算微平均指标；不要独立重采样同一录音的窗口或 clean/noise 版本。学习模型至少多个随机种子，随机预算基线也多个种子。

风险比例给置信区间，稀有事件另报告绝对数量。一个预先固定政策若在 n 个独立试验单位中没有 harm，其 95% 单侧二项上界为 `1 - 0.05**(1/n)`；n=299 时约 1%。同一节目切出 299 段不满足独立条件，多个候选政策/领域同时筛选需多重检验处理。用来源聚类 bootstrap 时称经验区间，不直接声称分布无关风险保证。

若目标为“质量基本不变”，事先指定非劣界，例如 Content 或人工信息保留允许下降多少；使用配对置信区间验证。差异不显著本身不能证明等价或非劣。

论文最重要的表：

1. 主表：方法、Content/Format/Filter/Rephrase、intended CER/MER、实质退化率、有效修复召回、累计成本和 finish p95。
2. 模块消融表：权重×协议、保护、验证、门控，各自独立归因。
3. 泛化表：未见来源、领域、别名与另一 ASR 后端；严格协议目前以中文为主，不直接外推英文。

最重要的图：质量—实际成本曲线、退化率—调用比例曲线，以及晚到改口的 ASR/显示/编辑时间线。再附几个有代表性的成功、误改、保守漏修和提示污染案例。

不能从以下证据推出论文主结论：测试通过→准确率提升；拒绝更多→更安全且有效；标准名更多→实体准确率更高；少调用→端到端更快；同一参考提取词库→未知实体泛化；旧响应不合法→新严格提示没有纠错能力。

建议推进顺序：

1. **冻结任务和旧基线。** 固定精修目标、当前模型与所有规则/词库；既有 500 配对材料只作开发。
2. **听音复核变化样本。** 先审核 157 条变化配对，并抽查不变样本及系统遗漏的问题，确认 Refiner 是否有足量真实可选择收益。两路相同只说明相对操作中性，不证明输入正确。
3. **建立独立自然录音与挑战集。** 在看系统结果前固定来源组和双参考协议。
4. **适配局部编辑，再评价 2×2。** 保留原权重与候选权重；不只看格式通过率。
5. **重采收益标签并训练门控。** 若改变 Refiner/提示/验证链，应重新确认标签，不能复用旧模型操作收益当成新模型真值。
6. **完整会话与真实性能。** 通过质量、误改、净成本与泛化联合结果决定论文主张；若当前规则基线已很省，允许学习门控没有净速度收益，并据数据调整贡献。
